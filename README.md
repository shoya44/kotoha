# ことは（kotoha）

Windows上で動く、個人用のテキスト会話AIパートナーです。会話をSQLiteに保存し、出来事や好みを記憶として整理して、次の会話で参照します。ターミナルとブラウザーから利用できます。

このREADMEと `docs/01〜05`・`docs/07` は現在の実装を基準にしています。`docs/06` は将来拡張の検討候補です。

## 主な機能

- 会話の保存と、CUI起動時の直近会話の復元
- エピソード記憶と意味記憶（事実・好み・継続話題・手続き）の抽出
- タグや記憶間の接続を利用した想起。よく思い出す記憶を先に返す
- 意味の近さによる想起。言葉が一致しなくても、関係のある記憶を思い出す（Ollamaが必要。無くても会話は続きます）
- 想起・再確認による有効期限の延長と、触れられない記憶の自動削除
- 記憶の一覧・詳細表示、保護、明示的な削除
- 時刻・前回からの間隔・その時間の様子・機嫌を踏まえた応答
- トークン認証付きWebチャット
- AivisSpeechでの読み上げと、音声入力による通話
- SQLiteのバックアップ（自動・手動、既定で最新7件を保持）
- 外出先から、ことばの調整・設定変更・通話の切断・再起動

会話生成と記憶整理にはGemini APIのOpenAI互換エンドポイントを使用します。会話・記憶はローカルに保存されますが、応答や整理に必要な会話と記憶の一部はAPIへ送信されます。

## 動作環境

- Windows、Python 3.10以上（コードの構文上の要件）
- Gemini APIキーと、APIへ接続できるネットワーク
- CUI：`httpx`
- Web：上記に加えて `fastapi`、`uvicorn`

APIの利用条件・料金・利用可能なモデルは、利用するアカウント側で確認してください。

## ワンクリック起動

通常は **`start.bat` をダブルクリック**します。ショートカット経由でも、バッチ自身のフォルダーを基準に起動します。

**タスクトレイに常駐させることもできます。** その場合コンソールは1枚も出ません。

```
.\kotoha.bat tray             いますぐ常駐する
.\kotoha.bat autostart on     Windowsのログイン時に常駐する
.\kotoha.bat autostart off    やめる
.\kotoha.bat autostart status いまの設定を見る
```

常駐すると、トレイのアイコンから次のことができます。アイコンを**左クリックで会話画面**が開きます。

| | |
|---|---|
| ことはを開く | ブラウザーで会話画面を開く |
| 手を貸す | 音声エンジンとOllamaを起こす・止める |
| （様子） | ことは・音声エンジン・Ollamaが動いているかを、押せない行として表示 |
| 入れ直す（再起動） | 本体を落として上げ直す。自分で上げた本体でなければ押せません |
| 終わる | 本体ごと終了する |

様子はアイコンにかざしても出ます。10秒ごとに裏で調べているので、メニューはすぐ開きます。
**ことはが止まっているときは、アイコンが沈んだ色**になります。

### ことはに聞く・頼む

容量やメモリの話をすると、ことはは**そのときだけ**PCの中身を調べて答えます。

```
しょうや: Cドライブの容量どれくらい残ってる？
ことは  : んー、Cドライブは98GBくらいかな。もういいじゃん、そんなの見てないでさ。
```

頼めば動かしてもくれます。**できるのは決めた操作だけ**で、一覧は `talk/actions.py` にあります。
ことはが好きなコマンドを組み立てられる作りにはしていません。何をしたかは `data/actions.log` に残ります。

| できること |
|---|
| 音声エンジンを起こす／止める |
| Ollamaを起こす／止める |
| 自分を入れ直す |

`KOTOHA_ACTIONS_ENABLED=false` で何もしなくなります。

## 通知

何かあったときと、ことはが暇なときに、iPhoneへ通知を送れます。送るところは[OneSignal](https://onesignal.com/) に任せています。Web Push を自前で作ると鍵と暗号化のために依存が増えるので、REST APIを1回叩くだけにしてあります。

### 準備

1. OneSignal でアプリを作り、**App ID** と **REST APIキー**を控える
2. `settings.bat` で `.env` に入れる（**REST APIキーは秘密です**。人に見せないでください）

```
KOTOHA_PUSH_ENABLED=true
KOTOHA_ONESIGNAL_APP_ID=（App ID）
KOTOHA_ONESIGNAL_API_KEY=（REST APIキー）
KOTOHA_PUSH_OPEN_URL=https://端末名.…ts.net
```

3. OneSignal 側の Site URL に、同じ Tailscale の URL を登録する
4. iPhoneで**ホーム画面に追加したことは**を開き、設定の「通知を受け取る」をオンにする

> **iPhoneは iOS 16.4 以降で、ホーム画面に追加したときだけ**受け取れます。Safariのタブから開いている場合は届きません。

### 届くもの

| きっかけ | 中身 |
|---|---|
| 音声エンジンやOllamaが**落ちた** | 「音声エンジンが止まったみたい」。落ちた瞬間だけで、繰り返しません |
| 空きが減った | 「Cドライブの空き、15GBしかないよ」。`KOTOHA_DISK_WARN_GB` を切ったとき一度だけ |
| **ことはが暇なとき** | ことはが書いた一言。会話としても履歴に残ります |
| **毎朝8時** | 日付・天気・傘・服装。ことはの言葉で |
| 頼んだ時刻 | 「あとで言って」と預けたこと |
| 根を詰めすぎ・夜更かし | 「ちょっと休みなよー」「まだ起きてるじゃん」 |

声かけは既定で止めてあります。使うなら次を設定してください。

```
KOTOHA_REACH_OUT_ENABLED=true
KOTOHA_REACH_OUT_AFTER_HOURS=5      会話が途切れてからの時間
KOTOHA_REACH_OUT_INTERVAL_HOURS=6   次に声をかけるまで空ける時間
KOTOHA_REACH_OUT_FROM_HOUR=9        声をかけてよい時間帯
KOTOHA_REACH_OUT_TO_HOUR=23
```

> **会話の中身は OneSignal を通ります。** 渡したくない場合は `KOTOHA_PUSH_SHOW_TEXT=false` にしてください。通知は「ことはから」とだけ出て、中身は開いてから読む形になります。

通知はすべて、ことはが**何か言ったこと**の結果として出ます。言わずに鳴ることはありません。開けば、通知と同じ言葉が会話に並んでいます。

同じころに重なったものは、**1通にまとめて**言います。立て続けに鳴らさないための間隔です。

```
KOTOHA_NOTIFY_GAP_MINUTES=10    前の通知からこれだけ空ける。0でまとめない
```

送れたかどうかは `data/notify.log` に残ります（鍵は記録しません）。

### あとで言って

会話のなかで頼むだけです。

```
しょうや: 明日の朝9時に歯医者だから、忘れないように言って
ことは  : 仕方ないなー。ちゃんと覚えとくけどさ。
```

「10分後」「明日の朝」のような言い方でかまいません。絶対時刻への読み替えは、現在時刻を渡してあるので向こうで済みます。時刻が来たら、いつもの通知で言ってきます。

預かっているものは、会話のときに本人も把握しています（聞けば答えます）。取り消したいときは次のとおりです。

```
kotoha.bat remind            預かっている一覧
kotoha.bat remind del 3      3番を取り消す
```

> PCを閉じていた間に過ぎたものは、**12時間より古ければ黙って畳みます**。起動したとたんに何件もまとめて言われても困るので。

#### あとでもう一度

いま手が離せないときは、通知から開いた画面に出る**「あとでもう一度言ってもらう」**を押すと、同じ用件を置き直します。

```
KOTOHA_SNOOZE_MINUTES=30    どれだけ先に置き直すか。0でこの機能を出しません
```

> **iPhoneでは通知そのものにボタンが出ません。** Safariが通知のボタンに対応していないためです。通知を開いた画面で押してください。Chromeで見ているときは、通知を開かずにボタンだけで済みます。

置き直すと**新しい頼まれごとが1件増えます**。元のぶんは言い終わったままで、二重には鳴りません。通知の道に載せるのは番号だけで、**用件そのものはOneSignalへ渡していません**。

### 見守り

```
KOTOHA_LOOKOUT_ENABLED=true
KOTOHA_LOOKOUT_SIT_HOURS=3      同じアプリをこれだけ続けたら休ませる
KOTOHA_LOOKOUT_LATE_HOUR=2      この時刻から
KOTOHA_LOOKOUT_MORNING_HOUR=5   この時刻までに起きていたら夜更かし扱い
```

前面のアプリは**もともと1分ごとに数えています**（名前だけで、窓の題名は読みません）。使っていなかったものを使うだけなので、新しく覗くものはありません。

一度声をかけたら数え直すので、続けていても間隔が空きます。夜更かしは一晩に一度だけ。

### 朝のひとこと

天気は [Open-Meteo](https://open-meteo.com/) から取ります。鍵もアカウントも要りません。

```
KOTOHA_BRIEFING_ENABLED=true
KOTOHA_BRIEFING_HOUR=8          何時に言うか
KOTOHA_BRIEFING_GRACE_HOURS=3   その時刻に寝ていた場合、何時間後まで遅れて言ってよいか
KOTOHA_LATITUDE=35.765          天気を見る場所
KOTOHA_LONGITUDE=139.810
```

傘と服装はこちらで決め、言い回しはことはに任せます。型にはめると人格が死ぬので。

| | |
|---|---|
| 傘がいる | 降水確率50%以上、または雨・雪・雷の予報 |
| 半袖 | 最高25℃以上 |
| 長袖 | 最高18〜25℃ |
| 上着 | 最高18℃未満 |

**天気が取れなくても挨拶はします。** 外のサービスが落ちて朝が消えるのは違うので。

常駐は**本体を子として動かし、落ちたら5秒後に上げ直します**。`start.bat` から先に上がっている
ときは横取りせず、見守るだけにします。二重に常駐することはありません。
うまく動かないときは `data/tray.log` を見てください。

1. Pythonの依存関係・APIキー・Webトークンを確認する。
2. 起動済みなら既存のチャットを開く。ポートが別アプリで使用中なら停止して案内する。
3. 初回を含め、DBテーブルを初期化する。
4. Webサーバーの起動後、Tailscale ServeでHTTPS配信を開始する。
5. Tailscale側のHTTPS URLへの接続を確認し、既定のブラウザーで開く。

起動した黒いウィンドウはサーバーです。利用中は開いたままにし、停止はそのウィンドウで **Ctrl+C** を押します。ブラウザーを閉じるだけでは停止しません。Tailscaleは終了時に切断しません。

`tools.bat` はWeb起動、CUI会話、状態・記憶の確認、DBバックアップ、Tailscale、README、設定編集、セットアップを選べるメニューです。メニュー番号は画面の1〜9、終了は0です。

Tailscaleのインストールとログインを済ませておいてください。配信に失敗した場合は理由を表示し、ブラウザーを開きません。起動済みのローカルサーバーは残るので、原因を解消して `start.bat` を再実行できます。Serve設定はバックグラウンドで保持され、次回起動時に再利用します。

通常のログは起動案内・配信URL・終了方法と、問題がある場合の警告・エラーのみです。詳細なサーバーログやアクセスログが必要な場合は `KOTOHA_DEBUG=true` にして再起動します。

## 初回セットアップ

### 1. Python環境とDBを準備する

**`setup.bat` をダブルクリック**します。PythonのWindowsランチャー `py` が必要です。仮想環境があれば再利用し、なければ作成します。続いて `requirements.txt` の依存関係をインストールし、DBを初期化します。パッケージ取得にはインターネット接続を使用します。

### 2. `.env` を設定する

`settings.bat` をダブルクリックし、Gemini APIキーとWeb用トークンを設定します。最小限の設定例は次のとおりです。

```dotenv
GEMINI_API_KEY=<自分のGemini APIキー>
GEMINI_MODEL=<利用可能なGeminiモデルID>
KOTOHA_WEB_TOKEN=<自分で用意した十分に長いランダムなトークン>
KOTOHA_WEB_HOST=127.0.0.1
KOTOHA_WEB_PORT=8000
```

山括弧を含む値は説明用のプレースホルダーです。実際の値へ置き換え、そのまま、または引用符で囲んで記載します。CUIだけなら `KOTOHA_WEB_TOKEN` は不要です。設定変更後はアプリを再起動してください。同名の環境変数が既に存在する場合、環境変数が `.env` より優先されます。

### 3. 起動する

以降のコマンドはプロジェクト直下のPowerShellで実行します。`kotoha.bat` 自身がプロジェクト直下へ移動して実行します。

**ターミナルで会話：**

```powershell
.\kotoha.bat start
```

終了は `/exit` または `Ctrl+C` です。引数なしで `kotoha.bat` を実行してもCUIが起動します。

**ブラウザーで会話：**

```powershell
.\kotoha.bat web
```

[http://127.0.0.1:8000](http://127.0.0.1:8000) を開き、`.env` の `KOTOHA_WEB_TOKEN` を入力します。停止はサーバーを起動したターミナルで `Ctrl+C` を押します。

`start.bat` と `kotoha.bat web` はどちらも起動時にDBテーブルを初期化します。トークンはブラウザーのローカルストレージに保存されます。

## コマンド一覧

| コマンド | 内容 |
|---|---|
| `.\kotoha.bat init` | DBとテーブルの初期化 |
| `.\kotoha.bat start` | CUI会話の開始 |
| `.\kotoha.bat web` | Webチャットの開始 |
| `.\kotoha.bat status` | DBパス・モデル・メッセージ数・処理時刻の表示 |
| `.\kotoha.bat test-llm` | APIへ短い生成リクエストを送って接続確認 |
| `.\kotoha.bat consolidate` | 未処理会話の記憶整理（対象があればAPIを使用） |
| `.\kotoha.bat note "…"` | ことは自身のことを記憶として書き込む（更新の共有） |
| `.\kotoha.bat memory` | 意味記憶の一覧 |
| `.\kotoha.bat memory episodes` | エピソード記憶の一覧 |
| `.\kotoha.bat memory semantics` | 意味記憶の一覧 |
| `.\kotoha.bat memory pinned` | 保護記憶の一覧 |
| `.\kotoha.bat memory tags` | タグの一覧 |
| `.\kotoha.bat memory show 1` | IDが1の記憶の詳細・接続・出典 |
| `.\kotoha.bat backup` | DBのバックアップ |

CUI会話中には、以下を入力できます。Webの入力欄は通常の会話用であり、これらの管理コマンドには対応していません。

| コマンド | 内容 |
|---|---|
| `/status` | 状態表示 |
| `/memory [episodes\|semantics\|pinned\|tags\|show <id>]` | 記憶の確認 |
| `/consolidate` | 未処理会話の記憶整理 |
| `/protect <id>` | 指定記憶を自動削除から保護 |
| `/forget <id>` | 指定記憶を即時削除（確認画面なし） |
| `/exit` | 終了 |

`/forget` は保護済みの記憶も削除します。対象ノードのタグ・接続・出典リンクも削除しますが、会話原文、他の記憶、バックアップは残ります。原文から同じ内容が再抽出される可能性もあるため、関連データ全体の消去を保証する操作ではありません。

## 声で話す

返答の読み上げと、音声入力での通話に対応しています。どちらもWebチャットの機能です。

**準備：** VOICEVOX互換の音声エンジン（AivisSpeech など）をインストールしておきます。AivisSpeech なら `start.bat` が画面を出さずにエンジンだけ起こすので、手で立ち上げる必要はありません（立ち上がりに15秒ほどかかります）。自分で起動しておきたい場合や、ほかのエンジンを使う場合は `KOTOHA_AIVIS_AUTO_START=false` にしてください。既定の接続先は `http://127.0.0.1:10101`、既定の話者はコハクのノーマル（`1878365376`）です。別の話者を使うときは、エンジンの `/speakers` で確認したIDを `KOTOHA_VOICE_STYLE_ID` に設定します。

**読み上げ：** 既定では止まっています。画面のアイコンから設定を開き、「声で話す」をオンにすると、返答が音声で再生されます。

**通話：** 入力欄の右にある電話ボタンを押すと、マイクからの音声入力が始まります。話しかけると認識したテキストが送られ、返答が読み上げられ、読み上げが終わるとまた聞き取りに戻ります。もう一度押すと終了します。読み上げ中はマイクを開かないので、スピーカーのままでも自分の声を拾いません。

音声入力にはブラウザのWeb Speech APIを使います。**Chrome / Edge が必要**で、認識のためにブラウザが音声をGoogleへ送信します。マイクの利用にHTTPSが必要なため、`localhost` 以外からはTailscale経由のHTTPS URLで開いてください。対応しないブラウザでは電話ボタンを表示しません。

音声エンジンが起動していなくても、テキストでの会話はそのまま続けられます。`KOTOHA_VOICE_ENABLED=false` で読み上げ機能ごと止められます。

## 外出先から直す

左上のアイコンから開く設定に、離れた場所から手を入れるための項目があります。iPhoneから片手で操作できるようにしてあります。

| 項目 | 使うとき |
|---|---|
| **ことばを直す** | 話し方や決まりごとを変えたいとき。保存すると次の発言から変わります |
| **設定を変える** | 返答のふり幅や声の種類など、よく触る6項目。再起動なしで反映されます |
| **記憶を見る** | ことはが何を覚えているか確かめたいとき。書き直し・保護・削除もできます |
| **ほかの端末の通話を切る** | PCを通話中のまま置いてきたとき |
| **再起動する** | 動きがおかしくなったとき |

「ことばを直す」は保存のたびに直前の内容を控えるので、おかしくなったら「ひとつ前に戻す」で戻せます。

**再起動は `start.bat` かタスクトレイ常駐から起動している場合だけ効きます。** アプリが終了コード42で落ち、バッチがそれを見て起動し直す仕組みです。押し間違い防止に2度押しで、押してから10秒ほどで画面が自動的に戻ります。`kotoha.bat web` で直に起動した場合は、再起動ではなく終了になります。

**通話は1台までです。** あとから通話を始めた端末が持ち主になり、前の端末は自動的に通話をやめます。

## 記憶の整理と保持

以下の件数・時間は初期値です。運用設定は `settings.bat` で変更できます。

直近会話は既定で5往復・3,000文字を上限に参照します。CUIでは起動時と返答後に未処理会話が10ターン以上あれば整理します。

Webでは60秒ごとに確認し、**会話が5分途切れてから**整理します。整理は会話と同じ順番待ちに並ぶため、話している最中に走ると返答が数秒止まります。通話ではそれがそのまま沈黙として聞こえるので、溜まっていても会話中は手をつけません。1回で20ターンまで処理できるので、間があけば追いつきます。

想起はタグの文字一致で探しますが、それだけだと「眠れない」から睡眠薬の記憶にたどり着けません。Ollamaが動いていれば、意味の近さでも探して6枠のうち2枠をそちらに回します。止まっていればタグ検索だけに戻り、会話はそのまま続きます。記憶を座標に直す処理は裏で回るので、会話を待たせることはありません。

記憶には有効期限があります。想起されたとき、整理で再確認・更新されたときに期限を延ばすので、よく思い出す記憶は残り、触れられない記憶だけが薄れていきます。期限は縮まらず、無期限の記憶が期限付きに変わることもありません。

保護されていない期限切れの記憶はメンテナンスで削除します。CUIでは終了時、Webでは最終忘却から24時間ごとに実行します。一度も実行していない場合は起動後の最初の確認で実行します。

会話原文は自動削除しません。保護解除や記憶訂正の管理コマンドはありません。

## 設定の変更

**`settings.bat` をダブルクリック**、または **`tools.bat` の8番**で変更します。

1. メモ帳で開く `.env` を編集する。項目ごとの説明はファイル内のコメントを参照。
2. 保存後、バッチの画面でEnterを押して設定を検査する。
3. 起動中のサーバーをCtrl+Cで停止し、`start.bat` で再起動する。

編集するファイルは **`.env` だけ**です。初回は作成し、既存ファイルには未記載の項目だけを追加します。APIキー、トークン、既存設定は上書きしません。メモ帳では認証情報も見えるので、画面共有時は注意してください。検査結果に設定値や秘密情報は表示しません。

| 分類 | 変更できる項目 |
|---|---|
| Gemini | APIキー、モデル、接続先、出力上限、タイムアウト、temperature、試行回数 |
| Web | トークン、待受アドレス、ポート、初期履歴件数 |
| 起動 | ブラウザー自動表示、Tailscale自動起動・Serve配信、HTTPSポート、Tailscaleのフォルダー、起動待ち時間 |
| 会話 | 直近会話の件数・文字数、Fastルート、判定文字数、デバッグ表示 |
| 音声 | 読み上げの有効・無効、音声エンジンの接続先、話者スタイルID、タイムアウト、エンジンの自動起動と配置先 |
| 記憶整理 | 未処理ターン数の閾値、Webの確認間隔・アイドル時間、バッチ上限、整理出力上限 |
| 記憶保持・想起 | エピソード・意味記憶の保持日数、忘却間隔、タグリセット日数、想起の件数上限 |
| 保存 | DBパス、バックアップ保持数、自動バックアップの間隔 |

例：`KOTOHA_BROWSER_AUTO_OPEN=false` でブラウザーの自動表示を止め、`KOTOHA_BACKUP_KEEP=14` でバックアップを最新14件保持します。Tailscaleの場所は `KOTOHA_TAILSCALE_DIR` にフォルダーを指定し、空欄なら標準インストール先を使います。

初期値は `.env.example` に一元化し、`kotoha/config.py` が読み込みと型・範囲の検査を担当します。優先順位は **環境変数 → `.env` → `.env.example`**。環境変数で上書きされる項目は保存後の検査で名前だけ表示します。通常の設定変更では `.env.example` やPythonコードの編集は不要です。

数値は項目の有効範囲で指定し、真偽値は `true` / `false` を使用します。引用符で囲んだ値やUTF-8 BOMにも対応します。値の後ろにコメントを付けず、コメントは独立した行に記載してください。

DBパスの変更はデータ移行を行いません。相対パスはプロジェクト直下が基準です。記憶の保持日数は新規記憶に適用し、既存の期限は書き換えません。バックアップ保持数を減らすと、次回のバックアップで古いファイルが削除されます。

画面のデザイン、DBの制約、記憶JSONの形式や本文上限など、アプリ内部の仕様は設定項目にはしていません。

## 保存先とバックアップ

通常の保存先は `data/kotoha.sqlite3` です。バックアップはDBと同じフォルダーの `backups/` に作り、設定した保持数を超えた古い `kotoha_*.sqlite3` を削除します（既定7件）。`.env` やプロンプトは含まれません。

前回から24時間が経っていれば、Webのバックグラウンド確認とCUIの終了時に自動で作成します。忘却より先に取るので、期限切れで消えた記憶も直前のバックアップには残ります。`backup` コマンドはいつでも手動で作成でき、こちらは自動実行の間隔に影響しません。

復元するときはCUIとWebを停止し、現在のDBを退避してから、選んだバックアップを設定中のDBパスへ配置します。起動後は `status` と記憶一覧で内容を確認してください。バックアップにも会話や記憶が含まれるため、元DBと同様に扱ってください。

## iPhone・リモート利用

PCとiPhoneを同じTailscaleネットワークに接続します。`KOTOHA_WEB_HOST=127.0.0.1` のまま `start.bat` を起動すると、Tailscale Serveがローカルサーバーへ中継します。PCで開いた `https://端末名.…ts.net` のURLをiPhoneでも開けます。Tailscale側URLでは初回にWebトークンを入力してください。

Serveの開始は `KOTOHA_TAILSCALE_SERVE_ENABLED=true`（既定）、HTTPSポートは `KOTOHA_TAILSCALE_HTTPS_PORT=443`（既定）です。別アプリがその配信ポートを使用している場合は上書きせず停止します。`settings.bat` で空いているHTTPSポートを指定してください。443以外はURLにポート番号が付きます。

配信はTailscaleネットワーク内に限定するServeを使用します。実行方式は [Tailscale公式のServe仕様](https://tailscale.com/docs/reference/tailscale-cli/serve) に基づきます。初回にHTTPS/Serveの利用を求められる場合は、Tailscale管理画面で有効化してから再実行してください。PCが停止・スリープしている間は利用できません。

サーバー停止後もServe設定は残ります。配信設定を解除する場合は、設定中のHTTPSポートを指定して `tailscale serve --bg --https=443 off` を実行します（443は設定値に合わせて変更）。`KOTOHA_TAILSCALE_SERVE_ENABLED=false` は次回の自動設定を止めるだけで、既存のServe設定は削除しません。

## トラブルシューティング

| 症状 | 確認事項 |
|---|---|
| APIキー未設定と表示される | `.env` の `GEMINI_API_KEY` を確認 |
| `fastapi` / `uvicorn` が見つからない | Web用依存関係を含むセットアップを実行 |
| `no such table` | Web起動前に `init` を実行したか、DBパスが正しいか確認 |
| トークンが無効 | `.env` と画面の入力を合わせ、設定変更後はサーバーを再起動 |
| 認証・モデルエラー | APIキーと、アカウントで利用可能なモデルIDを確認 |
| レート制限・通信失敗 | API利用枠と接続を確認。入力は保存され、応答がない状態で残る場合があります |
| `.venv` のPythonが起動しない | 仮想環境の元になったPythonが利用可能か確認 |

通知がiPhoneに届かないときは、`/static/pushtest.html` を開くと、通知の許可・購読ID・OneSignalの応答をその場で確かめられます。会話画面からは辿れない、調べるためだけの1枚です。
