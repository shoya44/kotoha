# ことは：設計の原則

他の文書が「何を、どう作ってあるか」を書くのに対し、この文書は**「なぜそう決めるか」**を書きます。迷ったときの拠り所です。

各項に、現在のコードがその原則に**従っているか**を記します。従っていないものは、直す対象です。

- ✅ 適用済み
- ⚠️ 未適用（現在のコードは従っていない）
- ❓ 未確定（決めていない）

---

## 1. 脳と器

**ことはの本体は、PC上で動く脳ひとつです。** SQLiteと、uvicornが提供するAPI。判断と処理は、すべてここが担います。

タスクトレイ、ブラウザ、PWAのアバターは**器**です。器の仕事は3つだけです。

- 脳から届いたものを、見せる・聞かせる
- こちらの言葉を、脳へ渡す
- 自分が生きていることを、脳に知らせる

| 決めごと | 状態 |
|---|---|
| 器は判断しない | ⚠️ `app.js` が差分の要不要を判断している |
| 器はポーリングしない | ⚠️ `app.js:59` で30秒ごと、`app.js:1473` で通話の生存確認 |
| 器は会話の状態を持たない | ⚠️ `lastMessageId` を器が管理している |
| 端末ごとの好み（声の大きさなど）は器が持ってよい | ✅ 脳が知る必要のない設定のため |

**向きを逆にします。** 脳から器へ流す（Server-Sent Events）。器は繋いで、届いたものを出すだけになります。

## 2. ことはは1人

**実体は、同時にひとつの器にしか宿りません。** 重複して実体化することは、この作りでは誤りです。

| 層 | 重複しうるか | 根拠 |
|---|---|---|
| 脳（発言の生成） | 起きない | `jobs.py:18` の `turn_lock` ひとつに、会話（`web.py:129`）・巡回（`jobs.py:240`）・見張り（`jobs.py:123`）が並ぶ。生成は直列 |
| 会話（文字として残る） | 起きない | `announce()` がDBに1回書くだけ |
| 実体（声・姿） | **起きうる** | 複数の器が同じ発言を拾って、それぞれ読み上げた場合 |

守るべきは**実体の層だけ**です。

**実体の所在は、脳が把握します。** 器が名乗り出て奪い合うのではありません。器が繋がっていること自体が、そこに居られるという証拠です。

| 決めごと | 状態 |
|---|---|
| 実体の所在は脳が決める | ⚠️ 未実装 |
| 届け先は脳が1つ選ぶ | ⚠️ 未実装 |
| 実体がどこにも無ければ、スマホへ通知する | ⚠️ 未実装 |
| 同じ発言が2つの器から聞こえてはならない | ✅ 現在は自発発言を読み上げていないため、まだ起きていない |
| 会話の文字は、複数の器に出てよい | ❓ 未確定（読むのは自由、喋るのは一箇所、という整理でよいか） |

## 3. 言うことと、届けること

**自発的な発言は、すべて `serve/announce.py` を通ります。言ったことが、そのまま会話に残ります。** 通知だけを送る道はありません。開いても何も無い通知は不親切で、あとから会話を辿れなくなるためです。

この原則は維持します。そのうえで、**「言う」と「届ける」を分けます。**

いまは結合しています。`announce.py:134` の門番が、

```python
if not notify.ready():   # OneSignalの設定が揃っているか、それだけ
    return ""            # 揃っていなければ、発言を生成すらしない
```

**外部の通知サービスの設定状況が、ことはが口を開いてよいかを決めている**状態です。同じ判定が `jobs.py` の4箇所（`:99` `:135` `:180` `:197`）にも複製されています。

| 決めごと | 状態 |
|---|---|
| 言うかどうかは、ことはの都合で決まる | ⚠️ 外部サービスの設定に縛られている |
| 届け方は、言う内容と独立に決まる | ⚠️ 未分離 |
| 同じ巡回で重なったぶんは1通にまとめる | ✅ 向こうに居るのは1人のため |

## 4. 持ち込まないもの

| 決めごと | 状態 |
|---|---|
| 依存を増やさない | ✅ `httpx` `fastapi` `uvicorn` の3つだけ |
| 脳を捨てない | ✅ 端末だけで完結させる案は見送った（[08](08_iPhone版仕様.md)） |
| ことはに自由なコマンドを組ませない | ✅ `talk/actions.py` の決め打ちのみ。実行は `data/actions.log` に残る |
| 将来の仮定のための抽象化をしない | ✅ |
| 一度しか使わない処理に共通化層を作らない | ✅ |

新しい仕組みを入れるときは、**既にあるもので足りないか**を先に確かめます。

## 5. のぞき見しない

**普段ことはが見るのは、PCの起動時間と、前面にあるアプリの名前の2つだけです。** ウィンドウの題名も、中身も、履歴も読みません（`talk/presence.py`）。

| 決めごと | 状態 |
|---|---|
| 機械の中身は、聞かれたときだけ調べる | ✅ 毎回プロンプトに載せない |
| 外へ出るものを明示する | ✅ 会話と記憶の一部はGemini APIへ。通知本文はOneSignalを通る（`KOTOHA_PUSH_SHOW_TEXT=false` で伏せられる） |
| 意味の近さを測る処理は、同じPCの中で完結させる | ✅ Ollama |

## 6. 迷ったら、取りこぼさない側へ

実体の所在が判断できないときは、**通知を鳴らす側に倒します。** 鳴りすぎは煩わしいだけですが、鳴らなければ頼まれごとを取りこぼします。

| 決めごと | 状態 |
|---|---|
| 判定に迷ったら通知する | ❓ 未確定 |

## 用語

**「モード」は使いません。** `mode` はすでに応答の重さ（fast / slow）を指していて、画面にも出ています（`talk/router.py`、`#mode`）。居場所を表す語には別のものを当てます。
