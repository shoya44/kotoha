# ことは：資料の地図

コードが正で、ここに書くのは**コードを読んでも分からないこと**——なぜそうしたか、何を約束しているか——です。実装の details はコード内のコメントにあります。

## 分割の基準

**1ファイル＝1つの問いに答える。読む人が誰かで分ける。**

| 読む人 | 知りたいこと | 読む場所 |
|---|---|---|
| 使う人 | 何ができるか・どう始めるか | [README](../README.md) |
| 全体を知りたい人 | どういう考えで作られているか | [01 コンセプト](01_コンセプト.md) |
| 〃 | 何がどう動くのか（機能単位） | [02 機能](02_機能.md) |
| 中の動きを追う人 | 1往復で何が起きるか、どこから取ってどこへ送るか | [03 処理フロー](03_処理フロー.md) |
| 直す人（画面） | 画面遷移とUIの決まり | [04 フロントエンド](04_フロントエンド.md) |
| 直す人（サーバー） | エンドポイントとプロセス構成 | [05 バックエンド](05_バックエンド.md) |
| 直す人（データ） | 項目設計とER図、持たないもの | [06 データベース](06_データベース.md) |
| 運用する人 | 設定・配信・控え・困ったとき | [07 運用と設定](07_運用と設定.md) |
| 経緯を知りたい人 | なぜやらなかったか、何が起きたか | [history/](history/) |

さらに次の3つを守ります。

1. **現行仕様と過去の記録を混ぜない。** いま動いているものは `docs/` 直下、終わった検討と事故の記録は `docs/history/` に置きます。両方を同じファイルに書くと、どちらが現行か読んで分からなくなります。
2. **同じことを2か所に書かない。** 重複した瞬間から片方が古くなります。詳しい場所へリンクします。
3. **数字には出典を書く。** 「0.62」「8秒」のような値は、どう測ったかを併記します。測っていない数字は書きません。
