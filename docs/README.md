# ことは：資料の地図

コードが正で、ここに書くのは**コードを読んでも分からないこと**——なぜそうしたか、何を約束しているか——です。実装の details はコード内のコメントにあります。

## 分割の基準

**1ファイル＝1つの問いに答える。読む人が誰かで分ける。**

| 読む人 | 知りたいこと | 読む場所 |
|---|---|---|
| 使う人 | 何ができるか・どう始めるか | [README](../README.md) |
| 全体を知りたい人 | どういう考えで作られているか、全体像、人間らしさの作り方 | [01 コンセプト](01_コンセプト.md) |
| 〃 | 何がどう動くのか（機能単位） | [02 機能](02_機能.md) |
| 〃 | 脳のどこが、どの処理に当たるか | [09 解剖図](09_解剖図.md) |
| 中の動きを追う人 | 記憶の固着・想起・忘却、発言の組み立て、手続き、LLMの使いどころ | [03 処理フロー](03_処理フロー.md) |
| 直す人（画面） | 画面遷移とUIの決まり | [04 フロントエンド](04_フロントエンド.md) |
| 直す人（サーバー） | エンドポイント、I/F、定期バッチ、監視、プロセス構成 | [05 バックエンド](05_バックエンド.md) |
| 直す人（データ） | 3層の記憶、項目設計とER図、持たないもの | [06 データベース](06_データベース.md) |
| 運用する人 | 設定・配信・控え・困ったとき | [07 運用と設定](07_運用と設定.md) |
| 数値を動かす人 | 仮置きした値と、モデル任せの箇所と、見直しの手順 | [10 気になる点と見直し手順](10_気になる点と見直し手順.md) |
| 絵を足す人 | どんな絵をどう作り、どこに置くか。どの状況でどの絵が出るか。器がそれをどう動かすか | [08 立ち絵の作り方](08_立ち絵の作り方.md) / [12 姿の決まり方](12_姿の決まり方.md) / [11 動き](11_動き.md) |
| 経緯を知りたい人 | なぜやらなかったか、何が起きたか、済んだ計画 | [history/](history/) |

さらに次の3つを守ります。

1. **現行仕様と過去の記録を混ぜない。** いま動いているものは `docs/` 直下、終わった検討・事故・済んだ計画は `docs/history/` に置きます。両方を同じファイルに書くと、どちらが現行か読んで分からなくなります。
2. **同じことを2か所に書かない。** 重複した瞬間から片方が古くなります。詳しい場所へリンクします。
3. **数字には出典を書く。** 「0.62」「8秒」のような値は、どう測ったかを併記します。測っていない数字は「仮置き」と書き、[10](10_気になる点と見直し手順.md) に集めます。
