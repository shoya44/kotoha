# 03 処理フロー

どこから取って、どう組み立てて、どこへ送るか。

## 外とのやりとり（一覧）

| 相手 | 何を | 向き | 鍵 | 落ちたら |
|---|---|---|---|---|
| Gemini（OpenAI互換API） | プロンプト → 返答 | 送信 | 要 | 返事なし。発言は残る |
| Ollama `bge-m3`（家の中） | 記憶の文 → ベクトル | 送信 | 不要 | 意味での想起だけが効かない |

| Tailscale | 配信（外から繋ぐ道） | ― | ― | 家の中からだけ繋がる |

**記憶とプロンプトの中身が出るのは Gemini だけ**です（通知の本文を載せる設定にすると OneSignal にも渡ります）。

## 会話1往復

```
発言
 │
 ├─ 発言を保存（turn_id を採る）
 │    └─ 直前が「発言だけ・同じ文」なら、その往復を使い回す（送り直し）
 │
 ├─ Fast / Slow を決める（router）
 │    ├─ FAST_ENABLED=false → 必ず Slow
 │    ├─ 40字超 / 疑問詞 / 過去を指す語 / 記憶の操作語 → Slow
 │    ├─ 機械のことを頼む語 → Slow（Fast は [DO:] を読まないため）
 │    ├─ 記憶のタグに当たる → Slow
 │    └─ それ以外 → Fast
 │
 ├─ 記憶を集める（Slow のみ意味検索まで）
 ├─ プロンプトを組み立てる
 ├─ Gemini へ送る（通話なら流しながら受け取る）
 │    └─ Fast の1行目が NEEDS_SEARCH → 同じ往復のうちに Slow でやり直す
 ├─ 返答からタグを外す
 ├─ 返答を保存・機嫌・記憶の利用実績・頼まれごと
 └─ 画面へ返す（＋ PC操作があれば最後に実行）
```

### プロンプトの組み立て

上から順に、空でないブロックだけを空行で継ぎます。

| # | ブロック | 中身 | Fast |
|---|---|---|---|
| 1 | 固定ルール | `prompts/fixed_rules.txt`。話し方の約束と内部タグの作法 | ○ |
| 2 | 人格 | `data/prompts/persona.txt` があればそれ、無ければ `prompts/persona.txt` | ○ |
| 3 | 時刻と状況 | 現在日時・曜日／今日の予定／前回の会話からの間隔／いまのことはの様子／機嫌とそのきっかけと薄れ具合／さっきまでの話題／姿の居場所／返事のなかった声かけ／覚えている件数／相手の様子／Claude Code の様子 | 一部 |
| 4 | PCの中身 | 機械のことを聞かれたときだけ。CPU・メモリ・ディスクと、頼める操作の一覧 | × |
| 5 | 預かっている頼まれごと | これから言う予定のもの | × |
| 6 | 基本情報 | 保護記憶（ピン留め） | ○ |
| 7 | 気になっていること | 続きのある話（`open_topic`）を最大2件。「続きを聞いてもいい。毎回は聞かない」と添える | × |
| 8 | 関連記憶 | タグ命中・意味の近さ・最近のエピソード | × |
| 9 | 直近の会話 | 最大 `RECENT_TURNS × 2` 件。字数超過時は古いほうから落とす | ○ |
| 10 | 今回の発言 | ユーザーの発言（ことはから話すときは、代わりに「何を言うか」の指示） | ○ |
| 11 | Fastの補足 | 「記憶の検索が要るなら1行目に NEEDS_SEARCH」 | Fast のみ |

**声をかけたのに返事がなかったことは、ことはに渡します**（`chat.unanswered`）。直近の会話の中に、ことはから始まった往復があり、1時間以上返事が無ければ「返事のなかった声かけ: 1回（最後は3時間前）」の1行が入ります。水に流すか根に持つかは人格に任せますが、あったことは渡します。渡さなければ、何も無かった顔で始めるしかありません。直近の会話だけを見るので、話しているうちに窓から出て薄れます。朝のひとこと（その日限り・`extractable=0`）は数えません。

**いまのことはの様子は日替わりです**（`figure.situation`）。時間帯ごとに数個の様子を人格の範囲で置き、絵と同じ式（日付と時間帯）で1つに決めます。同じ日・同じ時間帯なら何度聞いても同じで、さっき言ったことと食い違いません。毎日14時に必ず「おやつ」では、生活ではなく時刻表に見えるためです。

**続きのある話は、それと分かる形で渡します。** `open_topic` は想起で毎回2件まで確保し（`retrieve.OPEN_TOPIC_LIMIT`。出来事が続いた週でも押し出されない）、プロンプトでは「気になっていること」として関連記憶から分けます。混ぜると、モデルには済んだ話と区別がつかず、人格にある「そういえばあれ、どうなった？」が出ません。

機嫌は申告制です（`[MOOD:]` が来たときだけ変わる）。**きっかけも一緒に申告させます**（`chat.mood_reason`）。理由の無い機嫌は3〜4ターンに1回ころころ変わっていました（実測 36回/126ターン）。「今の機嫌: すねている。きっかけ: 返事がなかったから」と戻せば、次の往復も同じ機嫌でいられるし、相手が謝ったら直る道もできます。

機嫌は**黙っているあいだに段階的に薄れます**（`chat.mood_intensity`。半減期 `KOTOHA_MOOD_HALF_LIFE_HOURS`、既定1時間）。1時間で「薄れてきた」、2時間で「だいぶ薄れた」と機嫌の行に添え、3時間弱で時間帯ぶんに戻ります。話しているあいだは時刻が進むので薄れません。きっかけは機嫌と同じ寿命で、戻れば読まれません。

中身は**2つの数**です（`chat.mood_axes`。快−不快と元気−疲れ、それぞれ -1〜1）。ラベルはその座標（`MOOD_AXES`）で、申告した点から時間帯の下地の点へ、半減期で戻っていきます。語彙はラベルのままで、機嫌の行に「気分は少し沈み気味、元気は低め」のような言葉（`mood_words`）を添えます。5段の階段ではなく、連続した1本の道の上に居ます。

**相手への信頼**も1行渡します（`habits.trust_line`。「相手への信頼: 高い（頼まれごとを守っている）」）。習慣と同じ週の振り返りで、高い / ふつう / 低め のどれかに一段ずつ動きます。叱るかどうかはこれを見て決めます（`fixed_rules.txt`。高いなら「珍しいね」で済ませ、低めならちゃんと言う）。

**さっきまでの話題**も1行持ちます（`[TOPIC: 引っ越しの話]` → `app_state.topic`）。往復ごとにプロンプトを組み直しても話題は続き、直近12往復の窓が切れても「さっきまでの話題: 引っ越しの話（10時間前から）」として渡るので、翌日の「昨日の続きだけど」まで届きます。変わったときだけ書かせ、来なければ前のまま。`[TOPIC: なし]` で終わり、`KOTOHA_TOPIC_KEEP_HOURS`（既定24時間）で忘れます。**申告が無ければ、その時間帯ぶんで埋めます**（`talk/figure.py` の `MOOD_PRIOR`）。**時間帯に合わない機嫌は引きずりません**。深夜の「眠い」は朝になれば外れ、昼まで布団のままにはなりません。区切りの表は figure.py が1つだけ持っていて、絵と言葉で二重に持ちません。

**Claude Code の様子は、記録の末尾だけを読んで渡します**（`talk/coding.py`）。`~/.claude/projects/<場所>/<id>.jsonl` の最後の数行から、種類（返事で終わっているか、道具を使った直後か）と時刻だけを見ます。何を頼まれて何を書いたかは読みません。前面アプリの名前しか見ないのと同じ線引きです。「kotoha で Claude Code が作業中（2分前まで動いていた）」「otoport の Claude Code は作業を終えて、返事を待っている（12分前から）」のように1行で渡し、30分動きが無ければ「止まっているように見える」と言います。

記憶の1行は `- [id:12][09-18][event] 歯医者に行った` の形です。**ラベルが本文と同じ量を占めていた**ので、層は種類から分かるぶん省き、年も今年なら省いています。

### 記憶の集め方（想起）

```
発言 ＋ 直近会話
 │
 ├─ 保護記憶（pinned）           → 「基本情報」へ（上限 PINNED_LIMIT）
 │
 ├─ タグ命中                     ┐
 │   記憶のタグが文に含まれるか   │
 │   よく使われたタグ順に候補     │
 │                               ├→ 候補をまとめ、関連（memory_edges）を1hopたどる
 ├─ 意味の近さ（Ollama）         │   → 「関連記憶」へ（上限 RELATED_LIMIT）
 │   類似度 EMBED_FLOOR=0.62 以上 │      うち EMBED_RESERVE 件は意味枠として確保
 │                               │
 └─ 最近のエピソード             ┘

 発言の座標（1往復に1回だけ作る）
 └─ 日記の近さ                    → 「思い当たる日記」へ（上限 DIARY_RECALL_LIMIT。ここ数日ぶんは除く）
```

`EMBED_FLOOR` の 0.62 は、実際に当たった組の類似度の中央値から置いています。Ollama が止まっていればタグ命中だけで動きます。

### Gemini の入出力

| | |
|---|---|
| 送り先 | `{GEMINI_BASE_URL}/chat/completions`（OpenAI互換） |
| モデル | `gemini-3.5-flash-lite`（無料枠の範囲で使う想定） |
| 役割 | **すべて1件の user メッセージ**。固定ルールも人格も同じ1通に入れる |
| 上限 | `MAX_OUTPUT_TOKENS`、`TEMPERATURE`、`TIMEOUT_SECONDS` |
| 再試行 | `LLM_ATTEMPTS` 回。ただし 429（枠切れ）は**投げ直さない**（失敗も枠を食うため） |
| 通話 | `stream: true` で受け取り、文の切れ目まで来たぶんから渡す |

### 返答の加工

返ってきた文から、**必ずこの順**で外します。

1. `[USED: 1,2]` → 使った記憶のid（数字だけ拾う。Fast では保護記憶のIDだけ通す）
2. `[MOOD: すねている|返事がなかったから]` → 機嫌と、そのきっかけ（知らないラベルは捨て、前の機嫌を保つ。きっかけは40字まで）
2'. `[TOPIC: 引っ越しの話]` → さっきまでの話題（30字まで。「なし」は終わりの印）
3. `[DO: 名前]` → PC操作（表にない名前は捨てる。**Slow のみ**）
4. `[REMIND: 2026-09-18 09:00|歯医者]` → 頼まれごと（読めない時刻は黙って捨てる）
5. `strip_tags` で**ひと拭き** ── 崩れたタグが本文に残ると、そのまま画面に出るため

残った本文が返事です。保存するのも、この本文です（履歴にタグを残しません）。

### 流しながら喋る（通話）

```
Gemini ──（届いたそばから）──> 文の切れ目まで来たぶん ──> 1行1件のJSON ──> 画面
                                                              └─ 届いた順に読み上げの行列へ
最後に {"done": 返事・機嫌・預かり・last_id}
```

- **タグの途中では切りません。** 揃ったタグは外し、開きっぱなしの `[` から先は手元に置きます
- **Fast では使いません。** 1行目が `NEEDS_SEARCH` のことがあり、喋ってしまってからでは取り消せないため
- 途中で切れても、**言いかけたぶんは捨てません**。1文字も来ていないときだけ、投げ直しのある普通の道へ落ちます
- 生成は1本のスレッドの中だけで回します（**SQLiteの接続は、作ったスレッドでしか触れない**ため）

## 裏の巡回（60秒ごと）

3つを順に回します。どれかが落ちても残りは続け、**落ちたことは必ず書き残します**。

```
① 巡回（会話と同じ順番待ちに並ぶ）
   ├─ 朝の材料を先に取る ← ロックの外（天気・地震は各8秒待つため）
   ├─ 前面アプリを1つ数える
   ├─ 記憶整理   ← 未処理があり、かつ会話が途切れているとき
   ├─ 控えを取る ← 前回から24時間
   ├─ 忘却       ← 控えのあと（順番に意味がある）
   ├─ 言うことを集める（このあいだは鳴らさず預かる）
   │    頼まれごと → 朝のひとこと → 見守り → 暇なときの声かけ
   ├─ 預かったぶんをまとめて1通で言う
   └─ 姿を送り直す
② ベクトル（Ollama往復。並ばせない＝会話を止めないため）
③ 見張り（音声エンジン・Ollama・ディスク。確かめるあいだは並ばない）
```

**時計が回り始めるのは `serve/web.py` の lifespan だけ**です。取り込んだだけでは始まりません。

## 記憶整理

```
未処理の往復（最大20往復・20,000字）
 │
 ├─ 既にある近い記憶を添える（タグ命中・意味の近さ）
 ├─ Gemini へ「JSONで返せ」と頼む
 ├─ 検証 ── 層と種類の組み合わせ、字数（episode 400 / semantic 200）、日付、タグ
 ├─ 保存 ── source_key で重複しない。統合対象があれば既存を更新
 └─ 処理済みの位置を進める
```

失敗が3回続いたら、そのバッチは諦めます（**言えるまで毎分試すと、そのたびに枠を1回ずつ食う**ため）。

## ことはから言うときの道

```
何か言いたい（朝・頼まれごと・見守り・声かけ）
 │
 ├─ 口を開ける状態か（通知が使える or 姿が出ている）
 ├─ 間が空いていない or 巡回の最中 → 預かる（DBに置くので落ちても消えない）
 │
 └─ 言う
     ├─ 言葉を作る（Gemini）。作れなければ定型（plain）で言う
     ├─ 履歴に残す
     └─ 届ける ── 姿が見えていればふきだし／でなければ通知
          └─ 届かなかったら、作り直さず配り直す（次の巡回で）
```
