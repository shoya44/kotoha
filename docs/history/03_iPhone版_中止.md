## やめた理由

**代償が、得るものに見合わなかった**からです。

いちばん重いのは声ではなく、**想起の劣化**でした。ベクトル想起を入れて「眠れない」から睡眠薬の記憶を引けるようになった直後に、それを持たない版を配ることになります。実測では**発言の6割でタグが空振り**し、話題と無関係な近況を見て返す状態に戻ります。

配る版と手元版でロジックが二重になる負担も、この差を埋められない以上は割に合いません。

| 諦めるもの | 程度 |
|---|---|
| コハクの声 | 端末内蔵は Kyoko 1つだけ。実質「声なし」 |
| **ベクトル想起** | **タグ検索のみに戻る。空振り6割** |
| 実装の一本化 | 同じロジックを2か所で保守 |

配布そのものを諦めた形になります。人に見せたい場合は、**手元版を見せる**か、改めて別の道を検討します。

## 実機で分かったこと

iPhone 16 Pro 相当・ホーム画面アプリとして測定。**この構想以外にも使える事実**なので残します。

| 項目 | 結果 |
|---|---|
| **Gemini API をブラウザから直接** | **CORS が通る**（別オリジンから実測） |
| **Aivis Cloud API をブラウザから直接** | **CORS が通る**（コハクは公式モデルとして提供あり） |
| OPFS | **直接書ける**（Worker 不要） |
| WebAssembly / Service Worker | 使える |
| 保存容量の上限 | **約 3,932 MB** |
| **音声認識（Web Speech）** | **ホーム画面アプリでも使える** |
| 日本語の音声合成 | **Kyoko の1つだけ** |
| `opfs-sahpool` 方式 | COOP/COEP ヘッダが不要（GitHub Pages で足りる） |

> **音声認識が使える**のは収穫です。iPhone単体版とは無関係に、**iPhoneから通話する機能は成立する**ことが確かめられました。

> **`persist()` の可否と、記憶が日をまたいで残るか**は測り切れていません。中止したため、そのままにしてあります。

## これは何か

**人に渡して試してもらうための、最小構成**です。手元版の置き換えではありません。

### 入るもの

- 文字での会話
- 記憶（エピソード・意味記憶）、タグによる想起
- 記憶整理と忘却
- 人格・固定ルールの編集
- 記憶の一覧・編集
- 書き出しと読み込み

### 入らないもの

| | 理由 |
|---|---|
| 通話（音声入力） | 最小構成の外。土台が固まってから |
| **コハクの声** | AivisSpeechはサーバーソフトで、iPhoneでは動かない |
| **ベクトル想起** | bge-m3は1.2GB。端末に載らない。**想起はタグ検索のみ** |
| 自動バックアップ | 手動の書き出しに置き換える |
| 通話の持ち主管理 | 端末が1台なので不要 |
| 複数端末での共有 | 記憶は端末の中だけ。同期しない |

> ⚠️ **想起の質は手元版より落ちます。** 意味の近さで探す仕組みが無いぶん、実発言の6割ほどでタグが当たらず、直近の出来事だけを見て返すことになります（[処理フロー](../old/07_処理フロー.md#記憶の想起)の測定を参照）。ここは承知のうえで切っています。

## 全体構成

サーバーは1台も要りません。置き場に静的ファイルを置くだけです。

```
  静的ファイルの置き場（GitHub Pages など）
        │ HTTPS
        ▼
  iPhone（ホーム画面アプリ）
    ├─ 画面        index.html / style.css / app.js   手元版から流用
    ├─ 会話        chat.js / llm.js / retrieve.js    Pythonから移植
    ├─ 記憶        SQLite WASM（OPFS）                端末の中
    ├─ APIキー      暗号化して IndexedDB              端末の中
    └─ 人格        prompts.js（既定）＋ 端末の編集内容
        │
        ▼
    Gemini API へ直接（各自のキー）
```

通信先は **Gemini だけ**です。作者のサーバーを経由しません。

## 手元版との違い

| | 手元版 | iPhone版 |
|---|---|---|
| 実行 | Python + FastAPI | ブラウザのJavaScriptのみ |
| 記憶の置き場 | `data/kotoha.sqlite3` | OPFS上のSQLite |
| APIキー | `.env` | 暗号化して端末内 |
| 認証 | `X-Kotoha-Token` | **不要**（端末の中だけ） |
| 記憶整理 | 60秒巡回（会話が5分途切れたら） | **起動時と返答後** |
| 忘却 | 24時間ごとの巡回 | **起動時** |
| バックアップ | 自動・世代保持 | 手動の書き出し |
| 想起 | タグ ＋ 意味の近さ | **タグのみ** |
| 声 | AivisSpeech コハク | 端末内蔵（任意） |

**捨てる側が多い**のが要点です。サーバー用の約1,200行（`web` / `admin` / `voice` / `launcher` / `cli`）は移植しません。移すのは約950行、画面の約2,700行はそのまま使えます。

## 保存

### SQLite をそのまま端末へ

ブラウザ上のSQLite（WASM）を、**`opfs-sahpool` 方式**で使います。

この方式を選ぶ理由は1つです。**COOP/COEP ヘッダが要らない。** もう一方の `opfs` 方式はヘッダ設定が必要で、GitHub Pages では設定できません。sahpool ならその制約が消えます（Safari 16.4以降）。

結果として——

> **`db.py` のスキーマ、`retrieve.py` の想起クエリ、`consolidate.py` の保存は、SQL文をそのまま持っていけます。**

移植は「書き直し」ではなく、SQLを呼ぶ側の制御構造の移し替えになります。テーブル定義は [DB仕様](../old/02_DB仕様.md) と同一です（`memory_vectors` だけ使いません）。

> ⚠️ **`opfs-sahpool` は同時に1つしか開けません。** ホーム画面アプリとSafariのタブを同時に開くとエラーになります。握りつぶさず「別の画面で開いています。そちらを閉じてください」と画面に出します。

### 消えないか

端末にしか記憶がないので、消えたら戻りません。起動時に `navigator.storage.persist()` を申請し、結果を設定画面に出します。

> ⚠️ **申請が通らない端末では、書き出しが唯一の保険になります。** だから書き出しは「あると便利な機能」ではなく、**最小構成に含めます**。

## APIキーの守り方

キーは端末に残ります。**何から守れて、何から守れないか**を先に決めます。

### やること

```
① 初回にキーを入力する（伏せ字の入力欄）
② 端末内で AES-GCM の鍵を作る。extractable: false で作る
      → JavaScript からは鍵そのものを取り出せない
③ その鍵でAPIキーを暗号化し、暗号文だけを IndexedDB に置く
④ 鍵は「取り出せない形のまま」IndexedDB に置く
⑤ 使うたびに復号して、メモリ上でだけ持つ
```

平文をどこにも書かない、というだけの単純な仕組みです。実装は30行ほど。

### 守れること・守れないこと

| | |
|---|---|
| ✅ 保存領域を覗かれても、キーが読めない | 暗号文しか無い |
| ✅ 鍵を丸ごとコピーして持ち出せない | `extractable: false` のため |
| ✅ 設定画面のスクリーンショットに写らない | 末尾4文字だけ表示する |
| ❌ 端末のロックが解かれ、アプリが開ける状態なら防げない | その場で復号できてしまう |
| ❌ 配布元が悪意を持てば防げない | 同じ生成元のコードだから |

つまり **「うっかり見えてしまう」を防ぐ仕組み**であって、端末を奪われた場合の対策ではありません。**初回画面にその旨を1行書きます。**

Face IDによる起動時の施錠は、必要になったら足します（最小構成には入れません）。

## 会話の流れ

手元版の `/api/chat` が、そのまま端末内の関数呼び出しになります。

```
① 発言を messages に保存
② 直近の会話を読む（5往復・3,000字まで）
③ 記憶を集める（タグ想起 ＋ 直近の出来事）
④ プロンプトを組む
⑤ Gemini に送る
⑥ [USED:] [MOOD:] を外す
⑦ 返答・機嫌・利用実績を保存
⑧ 画面に出す
⑨ 未処理が溜まっていれば記憶整理（⑧のあと）
```

①〜⑦は [処理フロー](../old/07_処理フロー.md#会話テキスト) と同じです。違うのは**⑨が返答のあとに続くこと**と、**ロックが要らないこと**だけです。

### Gemini への接続

ブラウザから直接呼びます。別生成元からの呼び出しが通ることは実測済みです。

```
POST https://generativelanguage.googleapis.com/v1beta/openai/chat/completions
Authorization: Bearer <各自のキー>
```

失敗時の扱いは手元版と同じです。429は**再試行しません**（分あたりの枠は空いておらず、失敗ぶんも枠を食うため）。

## 記憶整理と忘却

裏で回す仕組みがないので、**前に出します**。

| | いつ | 条件 |
|---|---|---|
| 記憶整理 | **返答を出した直後** | 未処理が10往復以上 |
| 記憶整理 | **起動時** | 未処理が10往復以上 |
| 忘却 | **起動時** | 前回から24時間以上 |

考え方はCUI版と同じです（[処理フロー](../old/07_処理フロー.md#いつ走るか)）。手元版がわざわざ巡回にしているのは、整理が会話と同じ順番待ちに並んで沈黙を作るからでした。**iPhone版は通話がないので、返答を出したあとに走らせても困りません。**

整理中は画面に小さく印を出し、終わるまで送信を受け付けます（整理の完了は待ちません）。

## 書き出しと読み込み

**最小構成に含めます。** 端末から記憶が消えたときの唯一の保険だからです。

| | |
|---|---|
| 書き出し | SQLiteのファイルをそのまま取り出す。共有シート経由でファイルアプリやiCloudへ |
| 読み込み | ファイルを選び、**いまの記憶を置き換える**（統合はしない） |
| 促し | 最後の書き出しから14日たっていたら、設定画面に印を出す |

手元版の `data/backups/` と同じ形式なので、**手元版とファイルをやり取りできます**。

> ⚠️ **読み込みは上書きです。** 押す前に一度確認を挟みます（画面の「2回押し」の作法に合わせる）。

## 配布

| | |
|---|---|
| 置き場 | GitHub Pages（無料・HTTPS付き・ヘッダ設定不要） |
| 渡すもの | URLひとつ |
| 相手の準備 | Googleアカウントと、Gemini APIキーの取得（5分ほど） |
| 費用 | 利用者・配布者ともに **0円**（無料枠の範囲） |

### プロンプトの出どころは1つにする

人格や固定ルールを二重管理しないため、**`prompts/*.txt` を唯一の出どころ**とし、配布時に `prompts.js` へ焼き込みます。

```
prompts/*.txt ──┬→ 手元版（Python）が毎回読む
                └→ ビルド時に prompts.js を生成 → iPhone版の既定値
```

利用者が端末で編集した内容は端末に残り、既定値より優先されます。

> ⚠️ **人格の個人名は、git の外に置いてあります。** `prompts/persona.txt` は呼び名を「あなた」にしたひな形で、`data/prompts/persona.txt` を置くとそちらが勝ちます（`chat._read`）。配布時はひな形のまま渡し、各自が育てる形にします。

## 制約とリスク

| | 程度 | 対処 |
|---|---|---|
| **記憶が端末から消える** | 高 | 書き出しを最小構成に含める。`persist()` を申請 |
| **同時に1つしか開けない** | 中 | 画面に理由を出す |
| **想起がタグ検索だけ** | 中 | 承知のうえ。小型の埋め込みモデルは後日の宿題 |
| **APIキーが端末に残る** | 中 | 暗号化して置く。限界を初回画面に明記 |
| **キー取得が相手の障壁** | 中 | 初回画面を丁寧に作る |
| **手元版とロジックが二重になる** | 中 | プロンプトだけは一本化。配布版は**意図的に機能を増やさない** |
| 圏外では会話できない | 低 | Geminiが要る。画面だけはService Workerで出す |

> ⚠️ **配布版を手元版に追随させないでください。** 両方を育てると、同じロジックを2か所で直し続けることになります。配布版は「試してもらう版」と割り切り、**機能を止めておく**のがこの構成を保つ条件です。

## 作る順番

各段階で動くものが残るように切ってあります。

| | 内容 | 出来上がるもの | 目安 |
|---|---|---|---|
| **①** | SQLite WASM 起動・スキーマ作成・発言の読み書き。**実機で永続を確認** | 記憶が貯まる箱 | 1〜2日 |
| **②** | `llm` / `chat` / `retrieve`（タグのみ）を移植し、送信処理を繋ぎ替え | **会話できる** | 2〜3日 |
| **③** | `consolidate` と忘却。起動時・返答後に実行 | **記憶が育つ** | 2日 |
| **④** | キー登録画面・暗号化・書き出し／読み込み・Service Worker | **人に渡せる** | 2日 |

**②が終わった時点で、自分のiPhoneで単体の会話ができます。** そこで一度止めて、続けるか判断するのが安全です。

書き出し（④）は、`persist()` の申請が通らない端末だと保険が無い状態が続くため、**①の直後に前倒しすることも検討します**。
