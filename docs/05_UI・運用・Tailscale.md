# ことは：UI・運用・Tailscale

運用設定の数値は既定値です。変更は `settings.bat` から `.env` で行います。設定一覧は [README](../README.md#設定の変更) を参照してください。

具体的なセットアップとコマンド一覧は [README](../README.md) を参照してください。

## ダブルクリックでの起動

`start.bat` は依存関係・設定の確認、DB初期化、音声エンジンの起動、Webサーバー起動、Tailscale ServeのHTTPS配信、ブラウザー表示を行います。起動済みのサーバーはアプリ識別とトークンを確認して再利用します。ブラウザーはTailscale側URLでの応答を確認してから開きます。

### タスクトレイ常駐

`kotoha.bat tray` で、コンソールを出さずに常駐します（`pythonw.exe` から `tray.pyw` を呼ぶ形）。
`kotoha.bat autostart on` を実行すると、Windowsのログイン時に同じものが上がります。
登録先は `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` です。

```
トレイ常駐（pythonw）
  ├─ 本体を子プロセスで動かす（launcher。ブラウザーは開かせない）
  │    ├─ 終了コード42 → すぐ上げ直す（start.bat の役目を引き取る）
  │    └─ それ以外で落ちた → 5秒待って上げ直す
  ├─ すでに誰かが動かしていたら、子は作らず見守る
  ├─ 10秒ごとに様子を調べて覚えておく（メニューを開いた時に待たせない）
  └─ アイコンのメニュー（開く・様子・手を貸す・入れ直す・終わる）
       「手を貸す」は talk/actions.py の一覧をそのまま出すので、片方だけ増えない
```

画面を持たないので、起きたことは `data/tray.log` に残します。

> ⚠️ **`start.bat` と常駐を同時に使っても壊れません。** 先に上がっているほうが本体になり、
> あとから来たほうは見守りに回ります。ただし常駐側から「入れ直す」を押しても、
> 自分の子でなければ何も起きません。

> ⚠️ **トレイまわりは ctypes で直に書いてあります。** pystray と Pillow を入れれば短くなりますが、
> 依存3つで動いている構成に10MB超を足さないための判断です。アイコンは `kotoha.ico`（16〜64px）。

> ⚠️ **venvの python.exe は本体を子として起こすので、プロセスは常に2つ見えます。** 常駐が二重に
> なっているわけではありません。

> ⚠️ **風船（バルーン通知）は使っていません。** Windows 11 はトレイの風船を通知として扱うため、
> 集中モードや通知設定で黙って消されます。`Shell_NotifyIcon` は成功を返すのに何も出ない、という
> 気づけない失敗になるので、様子はツールチップとメニューに出しています。

`tools.bat` は起動、CUI、状態・記憶確認、バックアップ、Tailscale、README、設定編集、セットアップの操作メニューです。8番は `settings.bat` を呼び出し、`.env` の不足項目追加・編集・保存後の検査を行います。`setup.bat` は仮想環境・CUI/Web用依存関係・DBを準備します。

音声エンジンは `AivisSpeech-Engine/run.exe` を画面なしで起こします。GUIの `AivisSpeech.exe` は使いません。`/version` が応じれば起動済みとみなして二重には立ち上げません。立ち上がりを待たずに先へ進むので、起動直後の数十秒は読み上げだけが静かになります。見つからない・起こせない場合は理由を出して続行します。

Tailscaleのインストール・ログインは事前に必要です。配信できない場合は理由を表示し、ブラウザーは開きません。停止はサーバーのウィンドウでCtrl+Cを押します。通常のアクセスログは非表示で、KOTOHA_DEBUG=trueのときに表示します。警告・エラーは常に表示します。

## CUI

プロジェクト直下で `.\kotoha.bat start` を実行します。起動時はDBを初期化し、条件を満たせば整理してから直近会話の末尾最大6メッセージを表示します。最後の発言がユーザー入力だけなら未完了ターンの案内を表示します。

| 入力 | 動作 |
|---|---|
| 通常の文章 | 会話生成 |
| `/status` | DBパス、モデル、メッセージ数、前回会話・最終整理・最終忘却の時刻 |
| `/memory` | 意味記憶の一覧 |
| `/memory episodes` / `semantics` | 指定種類の一覧、最大30件 |
| `/memory pinned` | 保護記憶、最大50件 |
| `/memory tags` | タグ、最大100件 |
| `/memory show <id>` | 本文・日時・期限・保護・タグ・接続・出典ID |
| `/consolidate` | 記憶整理 |
| `/protect <id>` | 自動削除から保護 |
| `/forget <id>` | 保護状態を問わず即時削除。確認画面なし |
| `/exit` | メンテナンス後に終了 |

Ctrl+Cまたは入力の終端でも終了します。保護解除、手動訂正、タグ検索の管理コマンドはありません。

## Webチャット

`KOTOHA_WEB_TOKEN` を設定してから `.\kotoha.bat web` を起動します。起動時にDBを初期化するので事前の `init` は不要です。既定の接続先は `http://127.0.0.1:8000` です。

画面には認証入力、会話履歴、入力欄、送信ボタン、通話ボタン、応答待ち表示、時刻、処理モード、立ち絵、設定シートがあります。Enterで送信、Shift+Enterで改行します。返答は生成完了後に表示し、ストリーミングは行いません。管理用スラッシュコマンドはWebでは通常の文章として扱います。

立ち絵は時間帯で切り替わり、ときどきまばたきします。設定シートでは時刻表示と読み上げの切り替え、トークンの変更ができます。画面のファイルは `index.html` / `style.css` / `app.js` に分かれています。

| HTTP | パス | 内容 |
|---|---|---|
| GET | `/` | チャットHTML |
| GET | `/static/...` | 静的ファイル |
| GET | `/api/history?limit=40` | 会話履歴。既定40メッセージ |
| POST | `/api/chat` | `{"text":"発言"}` を受け取りreplyとmodeを返す |
| POST | `/api/speak` | `{"text":"読み上げる文"}` を受け取りwavを返す |
| GET/POST/DELETE | `/api/call` | 通話の持ち主の確認・主張・解除 |
| GET/PUT | `/api/prompts` | ことばの元になる3つの文の読み書き |
| GET/PUT | `/api/settings` | 画面に出している設定の読み書き |
| GET | `/api/memories` | 記憶の一覧。覚えたこと／できごと／保護の3種、各40件まで |
| GET/PUT/DELETE | `/api/memories/{id}` | 記憶1件の参照・本文の書き換え・削除 |
| PUT | `/api/memories/{id}/pinned` | 保護の切り替え |
| POST | `/api/restart` | 終了コード42で落ちる。start.batかトレイ常駐が起動し直す |

画面とファイル以外のAPIはすべて `X-Kotoha-Token` ヘッダーを検証します。画面・静的ファイルはトークン検証の対象外です。ブラウザーは認証成功時にトークンをlocalStorageへ保存します。WebはCtrl+Cで停止します。

## 読み上げと通話

`/api/speak` はVOICEVOX互換エンジン（AivisSpeechなど）へ本文を渡し、返ってきたwavをそのまま画面へ返します。既定の接続先は `http://127.0.0.1:10101`、既定の話者IDはコハクのノーマルです。読み上げは合計300文字で切ります。

本文は句点や改行で分け、1つ目を鳴らしながら次を合成します。合成にかかる時間は「0.7秒＋文字数×0.04秒」ほどなので、全文を一度に渡すより最初の声が早く出ます。10文字に満たない断片は前につないで、細切れの合成で間延びしないようにしています。エンジンが止まっている、`KOTOHA_VOICE_ENABLED=false`、本文が空のいずれでも503または400を返すだけで、会話は続きます。

通話は画面側の機能です。ブラウザのWeb Speech APIで聞き取ったテキストを通常の `/api/chat` へ送り、返答を読み上げ、読み上げが終わるとまた聞き取りに戻ります。読み上げ中はマイクを開かないため、スピーカー利用でも自分の声を拾いません。割り込みはできません。

話し終わってから返答が届かないときは、先に「えっと」などの短い間つなぎを鳴らします。数え始めるのは認識が確定した時点ではなく、話し終わりを検知した時点です。確定までの数百ミリ秒も相手にとっては無言の待ち時間になるためで、確定した時点で待ち時間を過ぎていればすぐ鳴らします。

待ち時間は0.4秒の固定です。発言の内容では変えていません。プロンプト1900字のうち発言が占めるのは14字ほどで、残りは毎回同じ規則と記憶なので、重い問いかけかどうかを発言から見分けられないためです。音声認識の結果には句読点も疑問符も付かないので、その手がかりもありません。音声は通話の開始時にまとめて作って使い回すので、鳴らすまでの待ちはありません。鳴らし終えたあと0.45秒おいてから本文に移ります。すぐ続けると畳みかけるように聞こえるためで、声も重なりません。すぐ返せたときは鳴らさず、同じ言葉が続けて出ないようにしています。音声エンジンが応じないときは間つなぎなしで動きます。

音声入力はChrome / Edgeが必要で、認識のためブラウザが音声をGoogleへ送信します。マイクの利用にHTTPSが必要なので、`localhost` 以外ではTailscale経由のURLを使います。対応しないブラウザでは通話ボタンを表示しません。

## 外出先からの操作

左上のアイコンから開く設定シートに、離れた場所から直すための項目があります。シートの中で画面を差し替える形なので、階層は1段までです。

| 項目 | できること |
|---|---|
| ことばを直す | 人格・会話の決まりごと・記憶整理の指示を書き換える。保存すると次の発言から効く |
| 設定を変える | よく触る6項目を書き換える。`.env` に保存してから設定を読み直すので、再起動は要らない |
| 記憶を見る | 覚えている内容を確かめ、本文を直す・保護する・消す |
| ほかの端末の通話を切る | PCを通話中のまま置いてきたときに使う |
| 再起動する | 動きがおかしくなったときの最後の手段 |

「ことばを直す」は保存のたびに直前の内容を1世代だけ控えます。おかしくなったら「ひとつ前に戻す」で戻り、もう一度押すと戻す前に戻ります。空では保存できません。

「設定を変える」で書き換えられるのは画面に出している項目だけです。ほかのキーを混ぜて送っても拒否します。範囲外の値も保存前に弾き、1つでも不正なら何も書きません。

「記憶を見る」では、覚えたこと・できごと・保護の3つを切り替えて一覧し、選ぶと本文・種類・日付・期限・ことば・もとの発言が出ます。本文を直すと、整理で直したときと同じく確認日時が進んで期限も延び、想起の近道はいったん解けます。消すときは2度押しで、保護していても消えます（CUI の `/forget` と同じ扱いです）。

「再起動する」は押し間違い防止に2度押しです。1度押すと赤くなり、5秒たつと元に戻ります。再起動を頼むとアプリは終了コード42で落ち、`start.bat` かタスクトレイ常駐がそれを見て起動し直します。画面は2秒おきに生存を確かめ、戻ってきたら会話画面に復帰します。90秒待っても戻らなければその旨を出します。

`kotoha.bat web` で直に起動した場合はバッチの繰り返しがないので、再起動ではなく終了になります。

## 通話は1台まで

通話の持ち主はサーバーが覚えています。端末は起動時にランダムな文字列を作って自分の名札にし、通話中は5秒ごとに「まだ自分の番か」を確かめます。

あとから通話を始めた端末が持ち主になり、前の端末は次の確認で気づいて通話をやめます。見張りが2分途切れた記録は無効になるので、PCが落ちたまま記録が残っても通話中のままにはなりません。

## Tailscale経由の利用

PCとiPhoneを同じTailscaleネットワークに接続します。アプリは127.0.0.1で待ち受け、Tailscale ServeがHTTPSで中継します。配信先URLはTailscaleの状態から取得します。別アプリやFunnelが同じ配信ポートを使用している場合は上書きせず、別ポートの指定を案内します。

Serveはバックグラウンド設定として保持します。停止・設定解除の手順と設定項目は [README](../README.md#iphone・リモート利用) を参照してください。PCの停止・スリープ中は利用できません。

## バックアップと復元

保存先はDBと同じフォルダーの `backups/`、保持は最新7件です。前回から24時間が経っていれば、Webのバックグラウンド確認とCUIの終了時に自動で作成します。忘却より先に取るため、期限切れで消えた記憶も直前のバックアップには残ります。`.\kotoha.bat backup` でいつでも手動作成でき、手動実行は自動の間隔に影響しません。

復元はCUI・Webを停止し、現在のDBを退避してからバックアップをDBの配置先に戻します。プロンプトと設定はDBバックアップには含まれません。復元後はstatusと記憶一覧で内容を確認します。

## 運用上の範囲

- 会話と記憶はSQLiteに保存し、応答・整理に必要な内容をGemini APIへ送ります。
- 明示削除はノードと関連リンクを削除します。原文、他のノード、バックアップ、API側の保持データは消しません。
- WebとCUIの同時起動をまたぐ会話の排他制御はありません。
- Webバックグラウンド整理の失敗は現在画面に表示されません。
- 読み上げ・通話はWebのみの機能です。CUIでは利用できません。
- `tests/` はいずれも一時DBだけを使う自動テストです。実DBには書き込みません。
