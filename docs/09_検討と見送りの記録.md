# ことは：検討と見送りの記録

**この文書は確定仕様ではありません。** 決める前に調べたこと、やらないと決めたこと、そう決めた理由を置く場所です。

現行仕様は [全体仕様](01_全体仕様.md) と、そこから辿れる文書を参照してください。仕様の側にこれらを混ぜないのは、**いま動いているものを読みたい人の邪魔になる**からです。逆にここを捨てないのは、同じことを二度調べたくないからです。

## まだやっていない候補

実装予定でも受入基準でもありません。必要が生じたときに範囲と費用を決め、既存の会話・保存・記憶処理を維持できる小さな変更から検討します。

| 候補 | 検討する条件 |
|---|---|
| 感情による想起の調整 | 口調は機嫌のラベルで調整済み。想起まで機嫌で変える必要が出た時。事実を感情で書き換えない |
| 学習候補の承認画面 | 記憶や手続きの自動更新を事前に確認したくなった時 |
| 記憶の統合・再要約 | 重複記憶の管理が難しくなった時 |
| 記憶の検索・訂正・保護解除UI | 現在の一覧・保護・削除だけでは管理が足りない時 |
| 記憶のグラフ表示 | 一覧と想起だけでは記憶のつながりを確かめきれなくなった時 |
| アバターの表情・動作 | 時間帯の切り替えとまばたき以上の表現が必要になった時 |
| 応答のストリーミング | 読み上げ開始までの待ち時間が気になった時。文単位で音声にすれば短縮できる |
| 通話中の割り込み | 読み上げ中に話しかけて止めたくなった時。マイクを開き続けるためヘッドホンが前提になる |
| PostgreSQL・常時稼働環境 | ローカルSQLiteとPC稼働時間では用途を満たせなくなった時 |
| 複数端末同期 | 同じWebサーバーへの接続以外に、端末ごとのデータ保持が必要になった時 |
| 用途別モデルの使い分け | 現在のGemini共通モデルでは品質・速度・費用の要件を満たせない時 |

導入するサービスやモデル、スキーマ変更、同期時の競合処理は、その候補に着手するときに決めます。

## 測ったうえで見送ったもの

### 記憶整理をローカルLLMへ移す（却下）

Geminiの無料枠（1日500回）を節約するため、手元の `qwen3.5-9b` に記憶整理をさせられないか試しました。

| 測ったもの | 結果 |
|---|---|
| 想起の一致 | **0.00〜0.03** |
| 1回の整理 | **8〜11秒**（中央値） |

枠は浮きますが、**整理の質が見合いません**。記憶整理は会話の土台を作る処理なので、ここが荒れると全体に効きます。却下しました。

測定中に引っかかった点も残しておきます。コンソールがcp932で文字化けする（`PYTHONIOENCODING=utf-8` で解消）、GPUが混んでいると1.5秒の待ち上限では足りない、考えごとのトークンが1,500の枠を食い尽くす（`/api/chat` を `think: false` で叩いて解消）。

### 配布・パッケージ化（見送り・2026-09-18）

友人に渡せるように、インストーラー＋初回セットアップ＋QRコードでiPhoneのPWAまで繋ぐ形を検討しました。

梱包そのものは軽い作業です。依存は `httpx` `fastapi` `uvicorn` の3つだけで、Python不要の実行ファイルにできます。**壁は梱包ではなく、使う人それぞれが自分のアカウントを揃える必要があること**でした。

| 要るもの | 同梱 | 自動化 |
|---|---|---|
| GeminiのAPIキー | 不可 | 案内とその場での検証は可能 |
| OneSignalのアプリ作成と2つのキー | 不可 | ダッシュボードの手作業が残る |
| Tailscale | 不可 | **配る側と使う側の両方の端末に要る** |
| AivisSpeech（数百MB） | 実質不可 | ダウンロード誘導まで |
| Ollama＋`bge-m3`（1GB超） | 実質不可 | ダウンロード誘導まで |

立ち絵（`serve/static/avatar/` の20枚と `kotoha.png`）は本人がStable DiffusionとChatGPTで作ったもので、再配布の制約はありません。ここは壁ではありませんでした。

再検討するなら、**インストーラーにキーを入力させない**形が良いと考えています。インストーラーは入れて起動するだけにして、設定はブラウザの初回セットアップ画面で受ける。押してその場で確かめられ、コピペが楽で、やり直せて、あとから同じ画面で直せるためです。必須は `GEMINI_API_KEY` と `KOTOHA_WEB_TOKEN` の2つだけで、残り約88項目は既定値のまま動きます。

### iPhone単体版（最小構成・中止）

サーバーを持たず、記憶もAPIキーも端末の中だけに置く構想です。実機で測った結果とやめた理由は [iPhone版（最小構成）仕様](08_iPhone版仕様.md) にまとめてあります。

## 起きたことと、そこから決めたこと

どれも**黙って失敗していた**ものです。同じ形（`except ... pass`、あるいは結果を確かめない）で、気づくまでに時間がかかりました。いま何をしているかは [処理フロー](07_処理フロー.md#黙って失敗しない) を参照してください。

### 通知が誰にも届いていなかった（2026-09-18）

宛先に `Subscribed Users` という束を指定していましたが、**この束はいまのアプリには存在しません**。OneSignalが最初に用意する束の名前は、アプリを作った時期で変わります。

無い束を指してもOneSignalは断らず、200を返したまま誰にも送りません。そして `push()` は状態コードしか見ていなかったので、「送った」と記録し続けました。**こちらの記録は13件、OneSignal側の控えは0件。**丸一日気づけませんでした。

→ 宛先を `Total Subscriptions` に変更。返事の本文まで見て、`errors` か宛先0件なら失敗として記録する。

### 裏の巡回が丸ごと止まっていた

順番待ちの名前を変えたとき、背景ループの側を直し忘れました。`NameError` は `except Exception: pass` に飲み込まれ、**記憶整理・バックアップ・忘却が静かに止まりました**。

→ ひと回りを `one_round()` にまとめ、落ちたものは必ず `data/notify.log` に残す。実際に一周させる回帰テストを追加。

### テストが本物の通知を送っていた（2026-09-18）

巡回をまるごと一周させるテストが、本物のGeminiを叩き、本物の通知を送っていました。**宛先が壊れていて誰にも届かなかったため、丸一日それに気づけませんでした。**宛先を直した直後のテストで、持ち主の電話が実際に10回鳴りました。

→ `tests/__init__.py` で外へつなぐ道を塞ぐ。黙って無視ではなく、その場で落とす。通知は既定で止め、鳴らす道を試すテストだけが自分で開ける。

### バックアップの失敗を握りつぶしていた

保存先の不調で忘却まで止めない、という判断自体は正しいものでした。ただ失敗を記録していなかったので、**控えが取れていないことに、要るときまで気づけません**。

→ 失敗を `data/notify.log` に残す。後段は今までどおり止めない。

## 決めごとの経緯（短いもの）

- **プロンプトの記憶行から層のラベルを外した。** 以前は `[id:12][2026-09-17][semantic/fact]` と36字あり、ラベルだけで本文と同じ量を占めていました。層は種類から決まるので書く必要がありません。`id` は `[USED:]` で返してもらうため残しています。
- **iPhoneのSafariは通知のボタンに対応していません。** 「あとでもう一度」を通知そのものに付けられないため、開いた画面に出す形にしてあります。Web Share Target も使えません。
- **記憶整理と通知は、3回続けて失敗したら諦めます。** 言えるまで毎分試すと、そのたびにGeminiの枠を1回ずつ食うためです。
