# 08 立ち絵の作り方

絵を足すときの、絵柄の決まり・作り方・置き方・つなぎ方。元の14枚は ChatGPT で作った本人作で、再配布の制約はありません。**描き足しは ComfyUI と本人 LoRA（`tools/sprite_gen`）で回す。** 2026-09-23 に LoRA で新ポーズ30枚を足した（いまは44枚）。LoRA 無しの2026-09 の生成分は絵柄が揺れて採用しなかった（下の「わかったこと」）。

## 仕組み（先に知っておくこと）

- 元絵は `img/dot/<名前>.png`（背景が**透明**なPNG）。`*-blink.png` は目を閉じた差分で、無くてもよい
- `python -m tools.build_sprites` で、足元と中心を揃えて `serve/static/sprite/` に焼く。**器はそれしか見ない**
- **名前は `talk/figure.py` の表と `sprites.json` の両方に要る。** 片方に無いと `tests/test_sprites.py` が落ちて気づける
- 様子（言葉）と絵は、同じ式（日付と時間帯）で1つに決まる。**時間帯の絵を様子と同じ数・同じ順に並べれば、言っていることと絵が自動で揃う**

## 絵柄の決まり

既存の絵（`img/dot/talk.png`, `snack.png`）を基準にする。

| | |
|---|---|
| 画風 | ちびキャラのドット絵風。輪郭は太めで均一。色は少なめのパステル。中に細かい階調があってもよい（焼くときに一度だけ縮める） |
| 大きさ | 1024×1024 で作り、人物は高さ 400〜420px 相当。既存は 418×401 前後 |
| 髪 | 腰まで届く、うねりのある薄いベージュブロンド。前髪は目にかかる |
| 目 | 赤茶。大きめ。まばたき差分は目を閉じた線だけ |
| 髪飾り | **左側頭部に紫の三日月**、房飾り（タッセル）付き。これが無いと別人に見える |
| 服 | 黒のオーバーサイズパーカー、**紐は薄紫**。薄いグレーのショートパンツ。白いスニーカーに紫の差し色 |
| 背景 | 白または無地。あとで透明にする |
| 向き | 正面〜やや斜め。**足元が見える全身**（床に揃えて置くため） |

## 作る（`tools/sprite_gen`）

生成・白抜き・まばたき差分は全部 ComfyUI 側で回す。**手で描く工程は無い。** 本人 LoRA は `poses.LORA` に名前を入れておけば、スクリプトが LoraLoader の節を挟む（`workflow_restyle.json` は触らない）。LoRA 無しでは絵柄が揺れる（下の「わかったこと」）。

```bash
python -m tools.sprite_gen                  # poses.py の全部を tools/sprite_gen/out/ に作る
python -m tools.sprite_gen --only happy,nap # 名前を絞る
python -m tools.sprite_gen --variants 4     # Seed をずらして候補を出す（選ぶ用）
python -m tools.sprite_gen --accept a,b     # 出来のよい絵を台帳（accepted.json）に載せる
python -m tools.sprite_gen --retry a,b      # だめな絵だけ Seed をずらして作り直す（台帳から外す）
python -m tools.sprite_gen --retry a --blink-only  # まばたきだけ作り直す
python -m tools.sprite_gen --apply          # 台帳にある絵を img/dot/ に置く（旧絵は img/dot/old/ へ）
python -m tools.sprite_gen.review           # out/ を 本体・まばたき・コマ の並びで review_N.png に
```

**全部いっぺんに揃えなくてよい。** 良いものから台帳に載せ、だめなものだけ作り直す。採否は人が見て決める（台帳に載せるのは人の判断）。
`out/<名前>/` に残すのは `<名前>.png` `<名前>-blink.png` `<名前>-f*.png` と `final_*_raw.png`（白抜き前。**次のポーズの元絵と LoRA の学習素材になる**）。`work/` と途中経過は消してよい。まばたきが失敗なら `-blink.png` を消すだけでよい（その絵はまばたきしないだけ。`--apply` は img/dot の古い差分も消す）。

- **表は `tools/sprite_gen/poses.py`。** 名前・`pose`・元にする絵（`source`）を1行足せば1枚増える。動きのコマは `frames={"f1": "...", "f2": "..."}` を足す（`<名前>-f1.png` になる）
- 土台のワークフローは `tools/sprite_gen/workflow_restyle.json`（API 形式）。元絵 → VAEEncode → KSampler → RMBG-2.0 で白抜き → 保存。差し込み（ドット化・目の窓）はスクリプトが節を足す
- **Seed は全体で1つ（`poses.SEED`）。** 変えると全部の筆致が変わるので、変えるなら全部作り直す
- 前提: ComfyUI が 127.0.0.1:8188 で起きていること。`ComfyUI-RMBG` の依存（cv2, onnxruntime, timm, transformers）が ComfyUI の venv に入っていること

### 仕組みと、そうなった理由

| | |
|---|---|
| 既存の絵（`source="self"`） | その絵を白い 1024 角に置き、`pixel art` 付きのプロンプトで **Denoise 0.6** の img2img。線と色がそろい、ポーズと構図は残る |
| 新しいポーズ | 姿勢の近い描き直し済みの絵（`source`）を元に、本人 LoRA ＋ `pixel art` 付きで **Denoise 1.0（実質 t2i）の1段だけ**。姿勢は文で決まり、元絵は大きさと位置の手がかりにしかならない。LoRA 無しの頃の2段（線画→ドット化→整える）は捨てた |
| まばたき | **出来た本体を元に、目の窓だけ塗り直す**（SetLatentNoiseMask、Denoise 0.8）。窓の外は本体そのもの。窓は中身の幅 28〜72%・高さ 20〜40%（寝そべりは 45〜68%。`poses.EYE_WINDOW` / `LOW_EYE_WINDOW`）。広くすると窓の中だけ髪の色が変わり、下に伸ばすと口が変わる。言い方は `poses.BLINK`（閉じた目を1本の線に）で、`eyes closed` だけだと片目をつぶる |
| 離れ小島 | 白抜き後、体につながっていない塊は落とす。プロンプトの「三日月の髪飾り」が背景に三日月を浮かせることがあるため |
| 動きのコマ | まばたきと同じ作り。**出来た本体を元に、脚の窓（幅 15〜85%・高さ 62〜100%）だけ描き直す**（Denoise 0.75）。上半身は本体そのものなので、コマ送りしても顔や髪が揺れない |

### 名前の決まり（器が名前で見分けるもの）

| 名前 | 使われ方 |
|---|---|
| `figure.GROUPS` / `ACT_SPRITES` にある名前 | 脳が決めて器に渡す姿。**表と `sprites.json` の両方に要る** |
| `walk`（コマ `f1`〜`f4`） | トレイが暇なときに歩く。脳の表には載せない。**まだ無い**（1周目の LoRA では横向きが出ない） |
| `fidget_*` | 暇なときの所作。トレイと会話画面が数秒だけ出して戻す。増やせばそのぶん種類が増える |
| `<名前>-blink` | まばたき。無い絵はまばたきしないだけ |

動きの仕組みは [11 動き](11_動き.md)。

### 絵柄が合っているかの目

髪飾り（左側頭部の紫の三日月と房）、紐が薄紫、靴の差し色が紫。この3つが揃っていれば同一人物に見える。Seed を固定しても、`source` を変えると顔立ちが動くので、新規は `--variants` で数枚出して選ぶ。

## 置いてつなぐ（生成のあとの手順）

絵ができたら、この順で器まで届く。**採否を決めるのは 0 で、それ以降は機械的。**

0. `python -m tools.sprite_gen.review` で見比べ、採用する名前を `--accept` で台帳に載せる。だめなものは `--retry`

1. `python -m tools.sprite_gen --apply` で `img/dot/<名前>.png` と `<名前>-blink.png` に置く（白抜きはすんでいる。**半透明の縁が残ってよい**）
2. 焼く。`python -m tools.build_sprites --check`。`--check` を付けると `img/blink-check.png` に、本体・まばたき・違い（赤）を横に並べた1枚が出る。**赤が目のまわりに無ければ、窓が外れている**（`EYE_WINDOWS` に足す）

   ```bash
   python -m tools.build_sprites --check
   ```

3. `talk/figure.py` の表に名前を足す。**様子と同じ数・同じ順に並べる**

   ```python
   "morning": ((
       "起きたばかりで、頭がぼーっとしている",
       "コーヒーだけ飲んで、二度寝しようか迷っている",
       "布団から出たくなくて、スマホをだらだら見ている",
       "起きてはいるが、まだ何もしていない",
   ), ("daydream", "coffee", "phone", "wave")),
   ```

   合う絵が無い様子は、近い絵を重ねて置く（おやつの様子2つに `snack` など）。数がずれると `tests/test_figure.py` が落ちる。

   機嫌ぶんは `ACTS` と `ACT_SPRITES` に足し、`act()` の `sulk` の下に判定を足す（`happy` がその形）。「疲れ気味」は絵を作ったが不採用（2026-09-23）で、いまは時間帯の立ち姿のまま。

4. テストを回す（名前の食い違いはここで落ちる）

   ```bash
   python -m unittest discover -s tests -t .
   ```

5. トレイを起こし直す（姿は別プロセスで、起動時に読み切る）

## LoRA を作る（`tools/sprite_gen/lora`）

絵柄を固定するための本人 LoRA。土台は生成と同じ Animagine XL 4.0。学習は Stability Matrix の kohya_ss（`C:\StabilityMatrix\Data\Packages\kohya_ss`）で回し、出来た LoRA は `Models\Lora\kotoha\` に落ちる（ComfyUI からは `kotoha/kotoha-00000N.safetensors`）。

```bash
python -m tools.sprite_gen.lora.prepare     # img/dot の本体14枚 → dataset/10_kotoha/（全身＋上半身の28枚と .txt）
tools\sprite_gen\lora\train.bat            # 学習。3070 で 1時間弱。epoch ごとに保存（6 epoch）
python -m tools.sprite_gen.lora.compare     # ComfyUI で epoch 別に t2i を回し compare.png に並べる（採否はここを見て人が決める）
```

| | |
|---|---|
| 素材 | **img/dot の本体14枚だけ。** `-blink` は目の線だけの差分なので入れない。**2026-09 の生成47枚は絵柄が揺れているので混ぜない**（揺れごと覚える） |
| 上半身の切り出し | 人物の上 55% を正方形に切って拡大。顔の学習密度を上げるため。左右反転は髪飾りが右に移って別人になるので**使わない** |
| キャプション | `kotoha, pixel art, chibi, 1girl, solo, white background, full body, <poses.py の pose 文>`。髪・髪飾り・服は書かない（トリガー語 `kotoha` に吸わせる） |
| 学習の値 | 768px・batch 1・dim 16 / alpha 8・UNet のみ・lr 1e-4 cosine・AdamW8bit・bf16・gradient checkpointing・latent と Text Encoder 出力はキャッシュ。繰り返し10 × 28枚 × 6 epoch = 1680 step |
| 8GB の壁 | Text Encoder のキャッシュが要るので `--shuffle_caption` は使えない（kohya が拒む）。VRAM が足りなければ末尾に `--fp8_base` |
| 使うとき | `poses.LORA` に名前を入れると `__main__._workflow` が LoraLoader（節 30）を挟む。prompt はトリガー語 `kotoha` で始まる。**新ポーズは Denoise 1.0（実質 t2i）で起こす。** 0.8 では元絵の姿勢が残りすぎて動かない。元絵は大きさと位置の手がかりにしかならない |

2026-09-23 の1周目は final（6 epoch）を採用。t2i でも元絵とほぼ同じ筆致が出る。弱点は横向き（walk が後ろ姿になる。横向きの素材が無い）。`Models/Lora/my_illustration_style_anima_lora*` は別件（土台が anima で Animagine には使えない）。

## LoRA で差分絵を足す手順（いつもの流れ）

LoRA ができてからは、新しい絵は次の順で足す。**手で描く工程は無く、人がやるのは採否だけ。**

1. `tools/sprite_gen/poses.py` の `POSES` に1行足す。`pose` は英語の姿勢の文、`source` は姿勢の近い既存の絵（大きさと位置の手がかりにしかならない。LoRA ありでは Denoise 1.0 で起こすので姿勢は文で決まる）
2. ComfyUI を起こす（127.0.0.1:8188）。**学習と生成は同じ 8GB を取り合うので、kohya を回している間は生成しない**
3. 作る。まとめて流してよい。1枚あたり約1分（本体＋まばたき）

   ```bash
   python -m tools.sprite_gen --only 名前1,名前2
   python -m tools.sprite_gen.review          # out/review_N.png に並ぶ
   ```

4. 見て決める。だめなものは Seed をずらして作り直す。まばたきだけなら `--blink-only`

   ```bash
   python -m tools.sprite_gen --retry 名前            # 本体ごと
   python -m tools.sprite_gen --retry 名前 --blink-only
   ```

   まばたきが片目ウインクや開いたままにしかならない絵（寝そべり・座りで顔が低いもの）は、`out/<名前>/<名前>-blink.png` を消して差分なしで採用してよい
5. 台帳に載せて、置いて、焼く

   ```bash
   python -m tools.sprite_gen --accept 名前1,名前2
   python -m tools.sprite_gen --apply
   python -m tools.build_sprites --check
   ```

6. 時間帯の絵なら `talk/figure.py` の表に足す（「置いてつなぐ」の 3）。`fidget_*` と `walk` は名前だけで器が拾うので表は要らない
7. `python -m unittest discover -s tests -t .` → トレイを起こし直す

### 知っておくこと

- **LoRA だけだと頭が小さく、背が高く出る**（頭が全身の 35% 前後。元の絵は 45% 前後）。新しいポーズには `poses.PROPORTION`（`(chibi:1.3), (big head:1.2), 2 heads tall` など）を自動で足す（2026-09-23 の surprised / doze から。それより前の30枚には入っていない）
- **LoRA だけだと髪が明るく白っぽく出る**（髪の明るさ 0.91 に対して元の絵は 0.875）。新しいポーズは生成後に `tools/sprite_gen/tone.py` が髪と肌の明るさを `talk` に寄せる（`poses.TONE_REF`）。本体で測った値をまばたきとコマにも使うので、目を閉じても色はちらつかない。これも surprised / doze からで、前の30枚は寄せていない
- **頭が大きい絵や座っている絵は、目が既定の窓（高さ 20〜40%）より下に来る。** まばたきが片目しか閉じないときは、その絵の `eye_window` を下げる（surprised / doze がそう）
- 横向き（walk）は1周目の LoRA では出ない（横向きの素材が無い）。2周目の課題
- LoRA を替えたら `poses.LORA` の名前を直すだけ。**Seed（`poses.SEED`）は変えない**
- 2周目の学習素材は `out/<名前>/final_*_raw.png`（白抜き前・白背景）。`lora/prepare.py` の集め先に足す

## 2026-09 の生成でわかったこと（LoRA 無しの限界）

47枚（既存14の描き直し＋新規33）を作ったが、**絵柄が微妙に揺れて採用に至らなかった。** 見比べ画像で並べると分かる程度の差で、1枚ずつ見ると気づかない。

| 試したこと | 結果 |
|---|---|
| 既存の絵を元に Denoise 0.6（`pixel art` 付き） | 筆致はそろい、ポーズはそのまま。**これだけは安定**。描き直しとしては使える |
| 新規ポーズを線画（0.85、`pixel art` 無し）→ ドット化 → 0.6 の2段 | 線が太く黒い線画のまま。ドット化しても戻らない |
| 新規ポーズを描き直し済みのドット絵から 0.8 で1段 | 筆致は近いがポーズの変化が小さい。髪が黄色く振れる（`pale beige`, 負に `yellow hair` で軽減） |
| Denoise 0.85 以上 | 顔が崩れて荒い 8bit 調 |
| 寝そべり（daydream / bored 元）を 0.75 以上 | 目が赤く崩れる |
| IP-Adapter（plus SDXL, `style transfer` 1.0〜1.2）で talk を参照 | **逆効果。** 色が濁って灰色がかり、輪郭が崩れる。重み 0 で無効化して節だけ残した |
| まばたき（LoRA あり） | 言い方を「closed eyes drawn as a single thin curved line, no upper eyelashes」にすると閉じた目が1本線になる（前は上まつ毛が残って二重に見えた）。**寝そべり・座りで顔が低い絵（phone / floor / fidget_hungry / cold / sit / cross / roll / kick）は片目ウインクか開いたままになる**ので `-blink.png` を置かず、まばたき無しで採用した |
| まばたき: 窓の inpaint | `red-brown eyes` を外し、窓を目の高さだけ（幅 28〜72%・高さ 20〜40%）にして Denoise 0.8 で両目が閉じる。0.6 は閉じない、0.9 は髪の色が変わる |

**結論: プロンプトと img2img の工夫では、同一人物を何十枚もそろえるには足りない。** それで LoRA を作った（上の「LoRA を作る」）。学習素材は `out/*/final_*_raw.png`（白抜き前・白背景・1024角）が使える。kohya_ss は Stability Matrix に入っている。8GB VRAM なので SDXL は 768px・batch 1・gradient checkpointing。

## つまずいたところ（同じ穴に落ちないために）

- **comfy-mcp は使っていない。** ツールがエラーで返るのと、往復が増えるため。ComfyUI の HTTP API（`/prompt` `/history` `/view` `/upload/image`）を直接叩くほうが速い
- `ComfyUI-RMBG` は入っていても依存が無いとノードが出ない。`cv2`・`onnxruntime`・`timm`・`transformers` を **ComfyUI の venv** に入れる（SAM や GroundingDINO は要らない。`groundingdino-py` は Windows でビルドに失敗する）。ComfyUI の再起動が要る。Stability Matrix の子プロセスは Manager の再起動が効かないので、プロセスを止めて同じ引数で起こし直す
- `FaceSegment` はちびキャラの顔を拾えない（人物写真向け）。目の窓は割合の矩形で切る
- `pixel art` を付けた txt2img は使えない。荒い 8bit 調になり、ドット絵風の元絵の質感と合わない。**元絵をドットに落として img2img** が唯一うまくいった道
- 生成の途中経過は `tools/sprite_gen/out/<名前>/` に全部残る（`pose_*_raw` が1段目、`final_*_raw` が白抜き前）。うまくいかない絵は、まずここを見る

## 決めごと

- **絵が無い様子は、その時間帯の立ち姿のまま。** 絵を待って様子を足さない、はしない。言葉が先で絵は後からでよい
- 同じ日のあいだは様子も絵も変わらない（`figure._pick`）。絵を足しても、この式は触らない
