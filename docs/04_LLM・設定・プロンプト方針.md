# ことは：LLM・設定・プロンプト方針

運用設定の数値は既定値です。変更は `settings.bat` から `.env` で行います。設定一覧は [README](../README.md#設定の変更) を参照してください。

## 接続先とモデル

会話生成・記憶整理にはGemini APIを使用します。`kotoha/talk/llm.py` がhttpxでOpenAI互換の `/chat/completions` へリクエストを送ります。

| 設定 | コード上の既定値 |
|---|---|
| `GEMINI_API_KEY` | 空。会話・整理・Web起動時に必要 |
| `GEMINI_BASE_URL` | `https://generativelanguage.googleapis.com/v1beta/openai` |
| `GEMINI_MODEL` | `gemini-3.5-flash-lite` |
| `KOTOHA_MAX_OUTPUT_TOKENS` | 1024 |
| `KOTOHA_TIMEOUT_SECONDS` | 60 |
| `KOTOHA_TEMPERATURE` | 0.7 |

モデルは会話・Fast・Slow・整理で共通です。別モデルへの自動フォールバックはありません。モデル名は実装上の既定値であり、API側の提供状況やアカウントでの利用可否を保証するものではありません。

設定例は [設定サンプル](../.env.example)、全設定項目と導入手順は [README](../README.md) を参照してください。`.env` はプロジェクト直下から読み込み、既存の環境変数を優先します。引用符で囲んだ値とUTF-8 BOMに対応します。インラインコメントは解析しません。

## プロンプト

| ファイル | 用途 |
|---|---|
| `prompts/fixed_rules.txt` | 会話の固定ルール |
| `prompts/persona.txt` | 名前・人格・話し方 |
| `prompts/consolidation_system.txt` | 記憶整理の指示と出力形式 |

会話時は、固定ルール、人格、時刻ブロック、保護記憶、関連記憶、直近会話、今回の発言を連結し、1件のuserメッセージとして送ります。空の記憶・会話ブロックは省略します。

時刻ブロックは4行です。現在日時と曜日、前回会話からの間隔（「たった今」「3日前」などの日本語）、その時間帯のことはの様子、直前までの機嫌を渡します。間隔を言葉にするのは、UTCで記録した時刻をそのまま渡すと時差のぶんだけ開いて見えるためです。様子の時間帯区分は画面のアバター切り替えと揃えています。

直近会話の既定値は5往復・3,000文字です。関連記憶は件数で制限しており、独立した「記憶1,200文字」の上限はありません。

## 出力形式

会話は通常のテキストです。利用した記憶は `[USED:1,2]`、機嫌は `[MOOD:眠い]` で受け取り、どちらも表示用本文と保存する履歴から取り除きます。閉じ括弧が欠けた場合や全角の `［］：` でも取りこぼさないよう、括弧は任意として行末までを上限に拾います。取りこぼすとタグがそのまま画面に出るためです。

機嫌のラベルは「ふつう」「機嫌がいい」「眠い」「疲れ気味」「すねている」の5つです。知らないラベルは捨てて直前の機嫌を保ち、記録から6時間が過ぎたものは「ふつう」に戻します。

Fastで検索が必要な場合は、1行目に `NEEDS_SEARCH` が返るとSlowへ切り替えます。

整理はJSONとして扱い、次の項目を読み取ります。

| 項目 | 内容 |
|---|---|
| `new_nodes` | 新規記憶候補。最大8件 |
| `edges` | 新規ノード間のderived_from接続。from/toはnew_nodes内のインデックス |
| `reconfirm_ids` | 再確認する既存記憶ID |
| `updates` | 既存記憶の本文更新。最大4件 |

整理時の出力上限は1,500トークンです。応答の最初の `{` から最後の `}` までをJSONとして解析します。API側のJSONスキーマ強制は使用していません。

## エラーと再試行

通信エラー、5xx、空の応答では、同じモデルへのリクエストを最大2回試行します。再試行間の待機処理はありません。400・401や応答形式不正などはエラーになります。

429（レート超過）は再試行せずエラーにします。分あたりの枠は間を置かずに投げ直しても空いておらず、失敗したリクエストも枠を消費するためです。画面には送信できなかったことを返します。

失敗時は架空の返答を保存しません。入力はAPI呼び出し前に保存されるため残ります。CUIではエラーを表示し、WebではLLMErrorをHTTP 502として返します。

## データの扱い

会話生成では現在の入力・直近会話・取得した記憶、整理では未処理会話・関連する既存記憶・再固定化候補をAPIへ送ります。読み上げではローカルの音声エンジンへ返答本文を送ります。音声入力を使う場合、ブラウザが認識のために音声をGoogleへ送信します。APIの料金、利用枠、データ保持条件は利用するサービス・アカウントの条件に従います。`.env` とDB・バックアップはGit管理対象外です。
