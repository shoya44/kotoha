# 05 バックエンド

## プロセス構成

```
scripts/tray.pyw（タスクトレイ・画面なし）
   └─ 子プロセスとして起動・見張り・落ちたら上げ直す
        launcher（kotoha.launcher）
           ├─ AivisSpeech / Ollama / Tailscale を必要なら起こす
           └─ uvicorn ── serve.web:app  ← 脳はここ**だけ**
                           └─ lifespan で 60秒の巡回を始める

scripts/mascot.pyw（デスクトップの姿）… 別プロセス。器のひとつ
kotoha.bat（CUI）………………………… 同じDBを直接触る道
```

- **脳はひとつ。** 巡回が立つのは uvicorn が app を serve するときだけです（[01 コンセプト](01_コンセプト.md) の⚠️）
- 会話と巡回は**プロセス内のロック1本**を共有します。CUI を同時に使うと、そこだけは排他になりません（文書化済みの制約）
- 画面からの「入れ直す」は終了コード **42** で落ち、`kotoha.bat` かトレイが上げ直します

## APIエンドポイント

すべて `X-Kotoha-Token` の見出しが要ります（合言葉は `secrets.compare_digest` で照合）。**見出しを付けられない道だけ** `?token=` を許します。

| メソッド | パス | 用途 |
|---|---|---|
| GET | `/` | 会話画面 |
| GET | `/OneSignalSDKWorker.js` | 通知の作業員（PWA用） |
| GET | `/api/push` | 通知の appId（空なら通知を使わない） |
| GET | `/api/history` | 履歴。`after` で差分だけ |
| POST | `/api/chat` | 会話（まとめて返す） |
| POST | `/api/chat/stream` | 会話（言い終わった文から返す）。1行1件のJSON。`{"say": 文}` が続き、最後に `{"done": {reply・mode・rest・last_id・kept}}`。通話が使う |
| GET/POST/DELETE | `/api/call` | 通話の状態・開始・終了 |
| GET | `/api/presence/stream` | 脳からの合図（SSE）※`?token=` 可 |
| POST | `/api/presence/here` | この器を見ている |
| POST | `/api/presence/bye` | 見なくなった ※`?token=` 可 |
| POST | `/api/restart` | 入れ直す（終了コード42） |
| GET | `/api/memories` | 記憶の一覧（`kind=semantic\|episode`） |
| GET/PUT/DELETE | `/api/memories/{id}` | 1件の取得・書き換え・削除 |
| PUT | `/api/memories/{id}/pinned` | 保護（ピン留め）の切り替え |
| GET | `/api/reminders` | 預かっている頼まれごと |
| DELETE | `/api/reminders/{id}` | 取り消し |
| POST | `/api/reminders/snooze` | あとでもう一度 |
| GET | `/api/machine` | PCの様子 |
| GET/PUT | `/api/prompts`・`/api/prompts/{name}` | 固定ルール・人格・整理の指示 |
| POST | `/api/prompts/{name}/revert` | 直前の版に戻す |
| GET/PUT | `/api/settings` | 設定の読み書き（`.env`） |
| POST | `/api/speak` | 文 → wav（いまの機嫌ぶんの表情つき。`plain: true` で素の声） |

書き換え系の注意:

- 記憶の本文は**層ごとに上限**（episode 400字 / semantic 200字）。整理が作る上限と揃えてあります
- 「ことばを直す」が書き換えるのは、**実際に効いている1枚**です。`data/prompts/` にあればそちら、無ければ `prompts/` のひな形。表示・保存・控え（`.bak`）・戻しがすべて同じ1枚を指します（会話を組む側と見る順を揃えないと、**保存は成功するのに発言が変わらない**）
- 設定の書き換えは `.env` を直し、`importlib.reload(config)` で反映します。**プロセスは止めません**
- 同じキーが2行あるときは**両方**書き換えます（読むほうは後ろの行を採るため）

## bat

**入り口は `kotoha.bat` の1枚だけです。** 叩くものが複数あると、どれを叩くのかを覚えないと始められません。長い中身とコンソールを出さないための `.pyw` は `scripts/` にあり、そちらは直接叩きません。

| 呼び方 | すること |
|---|---|
| `kotoha.bat` | 脳を起こす。終了コード42なら上げ直す（ダブルクリックもこれ） |
| `kotoha.bat setup` | Python環境を作り、依存3つを入れる。最初に1回 |
| `kotoha.bat settings` | 設定を対話で直す |
| `kotoha.bat tray` | タスクトレイに常駐（推奨）。本体を子として見張る |
| `kotoha.bat autostart on` | ログイン時に常駐させる（`off` / `status` も） |
| `kotoha.bat menu` | よく使うものを並べた画面 |
| `kotoha.bat rescue` | 管理者権限で復旧（詰まったとき） |
| `kotoha.bat status` ほか | CUI。`backup` / `memory` / `note` / 会話など |

`scripts/` の中身は `kotoha.bat` から呼ばれるぶんだけです（`setup.bat` / `menu.bat` / `rescue.bat` / `tray.pyw` / `mascot.pyw`）。

### 常駐の登録は、外に控えがある

ログイン時の起動（レジストリの `Run`）と5分ごとの見張り番（タスク `Kotoha Watchdog`）は、**`pythonw.exe` に `scripts/tray.pyw` のパスを渡す形で外に控えを持ちます。** 入口を動かすと古いパスが残り、黙って何も起きなくなります。そこで起動のたびに `autostart.repair()` が見て、`Run` は違えば黙って書き直します。見張り番は管理者権限で作られているため直せないことがあり、そのときだけ「`kotoha.bat rescue` をやり直して」と言います。

## 落ちたときの約束

- **黙って飲み込まない。** 巡回・整理・控え・通知の失敗は `data/notify.log` に1行残します（一度、巡回そのものが止まっているのに誰も気づけませんでした）
- 前段の失敗で後段を止めません（整理が落ちても控えと忘却は走る）
- 外が落ちても会話は続きます（声・ベクトル・天気・地震はすべて「無ければ無いなり」）
