# 05 バックエンド

脳（`serve/web.py` と、その中で回る巡回）と、それを起こして見張るもの。

## プロセス構成

```
scripts/tray.pyw（タスクトレイ・画面なし）
   └─ 子プロセスとして起動・見張り・落ちたら上げ直す
        launcher（kotoha.launcher）
           ├─ AivisSpeech / Ollama / Tailscale を必要なら起こす
           └─ uvicorn ── serve.web:app  ← 脳はここ**だけ**
                           ├─ lifespan で 60秒の巡回を始める
                           └─ HTTP / SSE で器とつながる

scripts/mascot.pyw（デスクトップの姿）… 別プロセス。器のひとつ
kotoha.bat（CUI）………………………… 同じDBを直接触る道
```

- **脳はひとつ。** 巡回が立つのは uvicorn が app を serve するときだけです（[01 コンセプト](01_コンセプト.md) の⚠️）
- 会話と巡回は**プロセス内のロック1本**を共有します。CUI を同時に使うと、そこだけは排他になりません（文書化済みの制約）
- 画面からの「入れ直す」は終了コード **42** で落ち、`kotoha.bat` かトレイが上げ直します
- 時計は `clock.py` の1本。DB に書く時刻も、経過の判定も、同じ「今」を見ます（SQLite の `'now'` は使いません）

## I/F 設計

脳と外のあいだにある口は、この5つだけです。

| 口 | 向き | 何が通るか | どこに |
|---|---|---|---|
| **HTTP API** | 器 → 脳 | 発言、記憶・頼まれごと・日記・設定・プロンプトの読み書き、声の合成 | 下の一覧 |
| **SSE** `/api/presence/stream` | 脳 → 器 | 実体の移動、姿の更新、ことはからの発言、通話の状態 | [04 フロントエンド](04_フロントエンド.md) |
| **内部タグ** | Gemini → 脳 | `[USED:]` `[MOOD:]` `[TOPIC:]` `[DO:]` `[REMIND:]` `[DROP:]`。本文から外してから画面へ | [03 処理フロー](03_処理フロー.md) |
| **ファイル** | 持ち主 → 脳 | `.env`（設定）、`data/prompts/`（人格）、`data/calendars/`（ゴミ・仕事） | [07 運用と設定](07_運用と設定.md) |
| **外部接続** | 脳 → 外 | Gemini、Ollama、AivisSpeech、Open-Meteo、P2P地震情報、OneSignal、Tailscale | [03 処理フロー](03_処理フロー.md) の一覧 |

器は HTTP と SSE だけで話します。器が DB や `.env` を直接触ることはありません（CUI だけが例外）。

## API エンドポイント

すべて `X-Kotoha-Token` の見出しが要ります（合言葉は `secrets.compare_digest` で照合）。**見出しを付けられない道だけ** `?token=` を許します。

### 会話

| メソッド | パス | 用途 |
|---|---|---|
| GET | `/` | 会話画面 |
| GET | `/api/history` | 履歴。`after` で差分だけ |
| POST | `/api/chat` | 会話（まとめて返す）。返事・mode・last_id と、預かった／取り消した頼まれごとの印 |
| POST | `/api/chat/stream` | 会話（言い終わった文から返す）。1行1件のJSON。`{"say": 文}` が続き、最後に `{"done": {reply・mode・rest・last_id・kept・dropped}}`。通話が使う |
| POST | `/api/speak` | 文 → wav（いまの機嫌ぶんの表情つき。`plain: true` で素の声） |
| GET/POST/DELETE | `/api/call` | 通話の状態・開始・終了 |

### 器と姿

| メソッド | パス | 用途 |
|---|---|---|
| GET | `/api/presence/stream` | 脳からの合図（SSE）※`?token=` 可 |
| POST | `/api/presence/here` | この器を見ている |
| POST | `/api/presence/bye` | 見なくなった ※`?token=` 可 |
| GET | `/api/push` | 通知の appId（空なら通知を使わない） |
| GET | `/OneSignalSDKWorker.js` | 通知の作業員（PWA用） |
| GET | `/api/machine` | PCの様子 |
| POST | `/api/restart` | 入れ直す（終了コード42） |

### 記憶・日記・頼まれごと

| メソッド | パス | 用途 |
|---|---|---|
| GET | `/api/memories` | 記憶の一覧（`kind=semantic\|episode`）。いまの強さつき |
| GET/PUT/DELETE | `/api/memories/{id}` | 1件の取得・書き換え・削除。書き換えは強さも足す |
| PUT | `/api/memories/{id}/pinned` | 保護（ピン留め）の切り替え |
| GET | `/api/diary` | 日記（新しい順）と、何となく覚えている習慣 |
| GET | `/api/reminders` | 預かっている頼まれごと |
| DELETE | `/api/reminders/{id}` | 取り消し |
| POST | `/api/reminders/snooze` | あとでもう一度（追いかけはここで消える） |

### 設定とことば

| メソッド | パス | 用途 |
|---|---|---|
| GET/PUT | `/api/prompts`・`/api/prompts/{name}` | 固定ルール・人格・整理の指示 |
| POST | `/api/prompts/{name}/revert` | 直前の版に戻す |
| GET/PUT | `/api/settings` | 設定の読み書き（`.env`） |

書き換え系の注意:

- 記憶の本文は**層ごとに上限**（episode 400字 / semantic 200字）。整理が作る上限と揃えてあります
- 「ことばを直す」が書き換えるのは、**実際に効いている1枚**です。`data/prompts/` にあればそちら、無ければ `prompts/` のひな形。表示・保存・控え（`.bak`）・戻しがすべて同じ1枚を指します
- 設定の書き換えは `.env` を直し、`importlib.reload(config)` で反映します。**プロセスは止めません**
- 同じキーが2行あるときは**両方**書き換えます（読むほうは後ろの行を採るため）

## 定期バッチ（裏の巡回）

60秒ごとに3本。順番と、走る条件。中身は [03 処理フロー](03_処理フロー.md)。

| 本 | 段 | 走る条件 | 上限・間隔 |
|---|---|---|---|
| ① 巡回（ロック内） | 前面アプリを数える | `PRESENCE_ENABLED` | 毎分 |
| | 記憶整理（固着） | 未処理の往復があり、会話が `IDLE_SECONDS` 途切れている | 20往復・8件。失敗3回で諦める |
| | 控え | 前回から `BACKUP_INTERVAL_SECONDS`（24時間） | 世代7本 |
| | 忘却 | 前回から `MAINTENANCE_SECONDS`（24時間）。控えのあと | ― |
| | 日記 | `DIARY_HOUR` 以降、前の日がまだなら | 1回の巡回に1日 |
| | 夜の整理 | 昨日の日記があり、今日まだなら | 1日1回。各4件 |
| | 習慣と信頼 | 日記が7日ぶん以上、前回から7日 | 週1回。習慣6件 |
| | 言うことを集めて1通に | 頼まれごと・朝・見守り・Claude Code・声かけ・そういえば | 通知の間 `NOTIFY_GAP_MINUTES` |
| | 姿を送り直す | 常に | 宛先は実体1つ |
| ② ベクトル（ロック外） | 記憶と日記を座標に。新しい記憶を近い記憶と結ぶ | `EMBED_ENABLED`、Ollama が応じる | 32件ずつ |
| ③ 見張り（ロック外） | AivisSpeech / Ollama / ディスク | 口を開ける状態 | 状態が変わった瞬間だけ |

順番に意味があります。**控えは忘却より先**（逆にすると消えた直後の状態しか残らない）、**日記は夜の整理より先**（整理は日記を材料にする）、**言うことを集めてから1通にする**（同じ分に重なった朝の一言と頼まれごとが2通にならない）。

## 監視処理

見張っているものと、気づいたときの出口。

| 見ているもの | 誰が | 気づいたら |
|---|---|---|
| 本体（uvicorn）が落ちた | トレイの `Supervisor` | 5秒で上げ直す |
| デスクトップの姿が落ちた | トレイの `Figure` | 5秒で上げ直す |
| トレイごと落ちた | Watchdog タスク（5分ごと） | 5分以内に上げ直す |
| AivisSpeech / Ollama が止まった | 巡回③ | 落ちた瞬間だけ、ことはが一言 |
| ディスクの空きが減った | 巡回③ | `DISK_WARN_GB` を切った瞬間だけ、一言 |
| 通知が届かなかった | announce | `notify.log` に残し、次の巡回で配り直す（作り直さない）。3回駄目なら30分先へ戻す |
| 巡回・整理・控え・日記・整理・振り返りの失敗 | 各段 | `notify.log` に1行。前段の失敗で後段を止めない |
| 暦（ゴミ・祝日・会議）の期限が近い | `talk/upkeep.py` | 朝の一言で知らせる |
| 常駐の登録（`Run` / Watchdog）のパスが古い | `autostart.repair()` | `Run` は黙って直す。Watchdog は管理者権限が要るので「rescue をやり直して」と言う |

## bat

**入り口は `kotoha.bat` の1枚だけです。** 叩くものが複数あると、どれを叩くのかを覚えないと始められません。長い中身とコンソールを出さないための `.pyw` は `scripts/` にあり、そちらは直接叩きません。

| 呼び方 | すること |
|---|---|
| `kotoha.bat` | 脳を起こす。終了コード42なら上げ直す（ダブルクリックもこれ） |
| `kotoha.bat setup` | Python環境を作り、依存3つを入れる。最初に1回 |
| `kotoha.bat settings` | 設定を対話で直す |
| `kotoha.bat tray` | タスクトレイに常駐（推奨）。本体を子として見張る |
| `kotoha.bat autostart on` | ログイン時に常駐させる（`off` / `status` も） |
| `kotoha.bat menu` | よく使うものを並べた画面 |
| `kotoha.bat rescue` | 管理者権限で復旧（詰まったとき） |
| `kotoha.bat status` ほか | CUI。`backup` / `memory` / `note` / 会話など |

`scripts/` の中身は `kotoha.bat` から呼ばれるぶんだけです（`setup.bat` / `menu.bat` / `rescue.bat` / `tray.pyw` / `mascot.pyw`）。

### 常駐の登録は、外に控えがある

ログイン時の起動（レジストリの `Run`）と5分ごとの見張り番（タスク `Kotoha Watchdog`）は、**`pythonw.exe` に `scripts/tray.pyw` のパスを渡す形で外に控えを持ちます。** 入口を動かすと古いパスが残り、黙って何も起きなくなります。そこで起動のたびに `autostart.repair()` が見て、`Run` は違えば黙って書き直します。見張り番は管理者権限で作られているため直せないことがあり、そのときだけ「`kotoha.bat rescue` をやり直して」と言います。

## 落ちたときの約束

- **黙って飲み込まない。** 巡回・整理・控え・通知の失敗は `data/notify.log` に1行残します
- 前段の失敗で後段を止めません（整理が落ちても控えと忘却は走る）
- 外が落ちても会話は続きます（声・ベクトル・天気・地震はすべて「無ければ無いなり」）
- 1日1回のもの（日記・夜の整理・そういえば）は、失敗しても**その日はもう試しません**。毎分やり直すと枠を食うためです
