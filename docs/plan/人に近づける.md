## 進め方の決まり

- **1段＝1 PR。** 段ごとに `python -m tools.check` が通ってから押す（CI と同じ検査）。
- **時間は `clock.py` 1本。** 日単位の経過は `tests/support.py` の `Clock` で止めて進める。SQLite の `'now'` は使わない（PR 0 で置き換え済み）。新しく `datetime.now()` を書かない。触ったモジュールは `clock.now()` に寄せる。
- **列を足すときは `MIGRATIONS`。** `SCHEMA` は新しいDBのため、`MIGRATIONS` は手元のDBのため。両方書く。
- **数字は測ってから決める。** 強さの初期値・減り方は、`KOTOHA_DEBUG` で `data/retrieve.log` を1週間ためて、`[USED:]` の比から置く。決めるまでは既定を保守的に（今の期限と同じ挙動になる値）。
- **プロンプトの語彙は変えない。** 機嫌のラベル、`[MOOD:]`、`[USED:]` はそのまま。中身だけ変える。

## 段1でやったこと（2026-09-22）

設計メモとの違いは1つ。`expires_at` をやめる代わりに、**強さから導いた「床を切る時刻」を `expires_at` に書く**ことにした。忘却の道・生存の判定・index が前のまま使え、列は `strength` と `strength_at` の2本で済んだ。

手元のDBの控え（6日分・2,420通・記憶190件）で改修前後の想起を比べた（LLM・Ollama は呼ばず、タグ命中だけ）。

| | 件 |
|---|---|
| 発言 | 1,199 |
| 渡す記憶が同じ | 877（73%） |
| 上位6件の中で並びが入れ替わる | 322（27%） |
| 何も渡さない | 0 |

入れ替わりは、確かめてから日が浅い意味記憶が、古い出来事より前に出る向き。逆算した強さの分布は、出来事の中央値 0.72、意味 0.95（新しいDBなので、まだ薄れていない）。

## 段2でやったこと（2026-09-22）

- 機嫌の薄れは、6時間で急に消える形から、半減期（既定1時間）の曲線に。段階は3つ（まだ強い / 薄れてきた / だいぶ薄れた）で、濃さ0.15を切ったら時間帯ぶんに戻る。話しているあいだは時刻が進むので薄れない（前と同じ）
- 話題は「変わったときだけ書く」タグ。来なければ前のまま続き、「なし」で終わる。ことは自身の独り言（`speak`）からも書ける
- `chat.py` の時計を `clock` に寄せた（`datetime.now()` が6か所）。時計を止めたテストで、話題の経過時間と機嫌の薄れを確かめられる

## 段3でやったこと（2026-09-22）

- 新しい表は `diary_vectors` 1つ。記憶の `memory_vectors` と同じ形で、裏の巡回が同じ回で作る
- 想起は `retrieve_all` が (保護記憶, 関連記憶, 思い当たる日記) を返し、`retrieve` は前の2つ組のまま。発言の座標を1回で済ませるため
- 意味の想起を切る（`EMBED_RESERVE=0`）と日記の想起も切れる。別々の口を増やさない
- 比べる相手が1つも無ければ Ollama に行かない（前からの約束をそのまま）

## 段4でやったこと（2026-09-22）

- `consolidate.py` に足すのではなく `review.py` を分けた。整理は「会話→記憶」、読み返しは「記憶→記憶」で、材料も出口も違う。混ぜると1回の失敗で両方止まる
- 寄せるときは残す方の強さを足す（段1の道）。同じことが何度も出てきた＝確かめ直した、という読み
- 材料が2件未満なら API を叩かない。印だけ付けて次の日へ

## 測るもの（段5以降の前に）

- `KOTOHA_DEBUG=true` で `data/retrieve.log` をためる。渡した記憶の数と `[USED:]` で申告された数の比。`STRENGTH_GAIN` を動かす材料
- `kotoha.bat status` の「機嫌が動いた回数」。半減期1時間が長いか短いかの材料（すねたまま何ターンも続くなら短く、すぐ戻りすぎるなら長く）
