# 人に近づける（着手前の計画）

[09 解剖図](../09_解剖図.md) の「軽くした部分」を減らしていく。**進行中の計画**で、終わった段は [history/](../history/) に記録として移し、ここからは消す。

## 進め方の決まり

- **1段＝1 PR。** 段ごとに `python -m tools.check` が通ってから押す（CI と同じ検査）。
- **時間は `clock.py` 1本。** 日単位の経過は `tests/support.py` の `Clock` で止めて進める。SQLite の `'now'` は使わない（PR 0 で置き換え済み）。新しく `datetime.now()` を書かない。触ったモジュールは `clock.now()` に寄せる。
- **列を足すときは `MIGRATIONS`。** `SCHEMA` は新しいDBのため、`MIGRATIONS` は手元のDBのため。両方書く。
- **数字は測ってから決める。** 強さの初期値・減り方は、`KOTOHA_DEBUG` で `data/retrieve.log` を1週間ためて、`[USED:]` の比から置く。決めるまでは既定を保守的に（今の期限と同じ挙動になる値）。
- **プロンプトの語彙は変えない。** 機嫌のラベル、`[MOOD:]`、`[USED:]` はそのまま。中身だけ変える。

## 段1の設計メモ（いちばん大きい）

- **列**: `strength REAL NOT NULL DEFAULT 1.0`、`used_count INTEGER NOT NULL DEFAULT 0`。`expires_at` は残すが読まない（1段のあいだは両方書き、次の段で列を落とす判断をする）。
- **上がり方**: 使われたとき `strength += gain × (1 + log(1 + 日数))`。間隔が空いてから思い出すほど、よく定着する（間隔反復）。
- **下がり方**: 日ごとに `strength ×= decay`。層で違える（episode は速く、semantic は遅く）。実装は「読むときに経過日数から計算」で、毎日全行を更新しない。
- **消える**: `run_maintenance` で `strength(now) < FLOOR` かつ `pinned = 0` を消す。控えを先に取るのは今と同じ。
- **想起**: `_by_meaning` の score を `score × f(strength)` に。タグ命中の並びも `strength` を先に。
- **既定値**: 今の期限（episode 30日 / semantic 180日）と同じ寿命になる `decay` を初期値にする。挙動を変えないまま列だけ入れ、ログを見てから動かす。

## 測るもの（段1の前に、1週間）

- `kotoha.bat status` の「機嫌が動いた回数」。段2の減衰の速さを決める材料。
