# ことは：デスクトップ常駐仕様

運用設定の数値は既定値です。変更は `settings.bat` から `.env` で行います。設定一覧は [README](../README.md#設定の変更) を参照してください。

PC画面にことはを常駐させるための仕様です。モジュールの役割分担は [AP仕様](03_AP仕様.md)、会話と記憶整理の流れは [処理フロー](07_処理フロー.md) を参照してください。

**実装ずみです**（2026-09-19）。素材の入れ替えは `tools/build_sprites.py` を走らせ直すだけで、コードは変わりません。

## 考え方

**ことはの本体は脳です。** 脳はPCの中に固定されていて、SQLiteとuvicornでできています。記憶も機嫌も判断も、すべてここにあります。

画面に出るものは**器**です。器は姿を映すだけで、何も決めません。

```
          ┌──────────── 脳（PC内・uvicorn + SQLite）────────────┐
          │  記憶・機嫌・判断・実体の居場所                      │
          └──┬──────────────────┬──────────────────┬──────────┘
             │ SSE              │ SSE              │ SSE
        タスクトレイ        会話画面（PC）     会話画面（iPhone）
          （ドット）                                （PWA）
```

**実体は1つだけです。** どの器に姿を出すかは脳が決め、脳が覚えています。器が自分で決めることはありません。

デスクトップアプリを起動すると脳が起き、タスクトレイのドットに実体化します。ここが家です。

## 器とできること

| | テキスト会話 | リマインド登録 | 通話 | 履歴を遡る |
|---|---|---|---|---|
| ドット（タスクトレイ） | ○（押すと一行の入力が出る） | ○（会話経由） | × | × |
| 会話画面（PC・iPhone） | ○ | ○ | ○ | ○ |

ドットにマイクがないため、通話だけは会話画面の仕事です。**ドットから通話を押したら、会話画面を開いて実体をそちらへ渡します。** 押した人から見れば通話が始まるだけで、器が入れ替わったことは意識しません。

リマインドは会話の中の `[REMIND:]` で預かるので（[処理フロー](07_処理フロー.md#頼まれごとを預かるremind)）、会話ができる器では自動的にできます。

## 実体の決まり

### 生まれる

| きっかけ | 実体化する先 |
|---|---|
| デスクトップアプリの起動 | ドット（家） |

### 移る

**移動はすべて明示的な行為の結果です。** 勝手には動きません。

| きっかけ | 移る先 |
|---|---|
| その器で**話しかける**（送信） | その器 |
| 通知から会話画面を開く | その会話画面 |
| ドットから通話へ誘導 | 会話画面 |

追い出された器は**外出中**になります。会話画面は看板（「外出中」＋押せば呼べる）、ドットは立て札です。

ドットは**手を振って（`wave`）から薄くなって消え**、居た場所に立て札を残します。歩いて出て行く絵は素材に無く、手を振るほうが素材に合っています。立て札は絵ではなく、ふきだしと同じ仕組み（不透明な角丸ウィンドウ）で描きます——**押せば呼び戻せる場所**になるので、隠してしまうより都合がよいということでもあります。

⚠️ **「呼ぶ」ボタンは作りません。** 話しかければ来るので、ボタンを押してから話すのは手数が1つ多い。看板と立て札自体は押せます（用が無いときに呼ぶ道）。

### 消える

**居場所は、閉じても消えません。**

| きっかけ | あと |
|---|---|
| 器が閉じた（タブを閉じた・背景に回った） | **居場所はそのまま。** 見ていないだけ。戻ればそこに居る |
| 脳が落ちた | すべての器が沈む |

⚠️ **iPhoneを裏に回してもPCへは戻りません。** ポケットにしまっただけで、置いてきたわけではないからです。移すのは呼ばれたときだけ（話しかける・立て札や看板を押す・通知から開く）。

⚠️ **「居場所」と「見ているか」は別のことです。** 見ていないあいだの言葉は、通知で届きます（[通知の分かれ道](#通知の分かれ道)）。

⚠️ **席を外しても実体は解けません。** ドットは右下に居たままです。誰も見ていない場面のために状態を増やさない、という判断です。席を外しているかどうかは、通知の分かれ道でだけ効きます。

会話画面の名乗り（`web-…`）は**端末ごとに覚えます**（`localStorage`）。開き直しても同じ器として戻れるので、ことははそこで待っていられます。

### 脳が持つもの

```python
body = {
    "where": "desktop" | "web:<接続id>" | None,
    "since": "2026-09-19T08:12:00Z",
    "reason": "起動" | "話しかけられた" | "通知から開かれた" | "器が消えた",
}
```

脳のメモリが正です。**変わったときだけ `app_state` に書き写します。** 移動は1日に数回なので、書き込みはほとんど発生しません。書き写す理由は3つ：

1. ことは自身が居場所を言えるようにする（プロンプトに1行入れる）
2. 脳を上げ直したときの手がかりを残す
3. 管理画面やログから見えるようにする

## 通知の分かれ道

ことはが口を開くのは `announce()` だけです（[処理フロー](07_処理フロー.md#ことはから何か言うannounce)）。ここに分岐が1つ入ります。

```
文ができた → messages に保存（ここは今までどおり）
   │
   ├── 実体なし ────────────> Push（OneSignal）
   │
   ├── 居場所はあるが、その器は見ていない ──> Push
   │   （タブを閉じた・iPhoneを裏に回した）
   │
   ├── 実体が会話画面 ──────> その器へ say（見ているので鳴らさない）
   │
   └── 実体がドット ────────> PCの最終入力からの経過を、ここで1回だけ測る
          ├── 5分未満 ──────> ふきだしに出す
          └── 5分以上 ──────> Push。ふきだしは出さない
```

⚠️ **離席の判定は、この瞬間にしか行いません。** 巡回では測りません。ことはが口を開くのは1日に数回なので、`GetLastInputInfo` を常時見張る理由がありません。

⚠️ **器に申告させません。** 器が落ちていても判定が効くようにするためと、器が嘘をつく余地をなくすためです。

⚠️ **口を開けるかどうかの条件も変わります。** これまで自発発言はすべて「Pushが使えること」を前提にしていました（`notify.ready()`）。姿が出ていれば、通知が無くても言えます。`announce.can_speak()` が `Pushが使える、または器が繋がっている` を見ます。

席を外しているあいだ `say` を送らないので、戻ってきてもふきだしは溜まっていません。会話履歴には残ります。

## 絵の決まり

### 判定は脳が持つ

`talk/figure.py` が唯一の持ち主です。**器は名前を受け取って描くだけ**なので、ドットと会話画面で違う絵が出ることは構造上ありません。

```python
group(hour)      -> "night"       # 時間帯
situation(hour)  -> "夜更かし中で…" # プロンプトに入れる言葉
sprite(now)      -> "cards"       # その日の立ち姿（日付で1枚に固定）
act(hour, mood, said_ago, streak_hours) -> "idle"
picture(hour, now, …) -> "cards"  # 実際に描く1枚。器はこれだけを受け取る
```

⚠️ 時間帯の区切りは、これまで `chat.situation()` と `app.js` の `getAvatarGroup()` に二重にありました。**`figure.py` に集めて、`chat.py` はそこから読みます。** `app.js` 側の表は削除します。

| `act` | いつ |
|---|---|
| `talk` | 自発発言を出した直後 |
| `sleep` | 深夜、または機嫌が「眠い」 |
| `worry` | 同じアプリを `LOOKOUT_SIT_HOURS` 以上続けている |
| `sulk` | 機嫌が「すねている」 |
| `idle` | ほかに当てはまらないとき |

`idle` 以外には専用の絵があります（`figure.ACT_SPRITES`）。`idle` のときだけ、その時間帯の立ち姿をそのまま出します。**どちらを出すかは `figure.picture()` が決めます**——器に選ばせません。

見送りとお別れ（`leave` / `arrive`）は器の中だけの状態です。脳は知りません。

### 素材

ドット絵に統一します。元の絵は `img/dot/` に置き、`tools/build_sprites.py` で整えてから
`serve/static/sprite/` に書き出します。**会話画面はHTTPで、ドットはディスクから、同じ場所を見ます。**

| 実寸 | 大きさ | 使う場所 | 出す大きさ |
|---|---|---|---|
| `full/` | 141×140 | タスクトレイのドット | 141px（画面の点と1対1） |
| `web/` | 413×410 | 会話画面のアバター | 140ポイント＝**420画素**（iPhone） |
| `face.png` | 192×192 | 会話の行やヘッダーに出る顔 | 34〜56ポイント＝最大168画素 |
| `icons/icon-*.png` | 120〜384 | ホーム画面と、鍵の画面 | 180画素／450画素 |

⚠️ **画面の点と、絵の点は同じではありません。** iPhoneは1ポイントを3画素で描くので、
140ポイントの枠に140pxの絵を置くと3倍に引き伸ばされて眠くなります。**常に「縮める側」に
なる大きさで出す**のが基本です。

⚠️ 元絵は418pxなので、顔まわりで取り出せる細かさは**280px相当が上限**です。鍵の画面
（450画素）だけは、そこから少し引き伸ばしています。これ以上あげるには元絵から要ります。

⚠️ **アイコンは要る大きさぴったりで出します。** 1枚だけ置いて端末に縮めさせると、輪郭が潰れて荒く見えます。透けたままだとiOSでは黒く塗られるので、下地を敷いてあります。



⚠️ **拡大しません。** 元の絵はドット風ですが、中に細かい階調を持っていて（色数1万超）、
きれいな格子になっていません。整数倍に拡大しても崩れるだけです。**一度だけ面積平均で
縮めて、その実寸を持ちます。**

⚠️ **足元を揃えるのは必須です。** 元の絵は1枚ずつ中身の大きさも位置も違います
（外接矩形で 311×382〜401×317）。そのまま切り替えると、絵が変わるたびに位置が跳ねます。
横は中央、下は床に合わせて同じキャンバスへ並べ直します。

⚠️ **まばたきは本体と同じ置き方をします。** 別々に測ると、まばたきのたびに顔がずれます。

#### 割り当て

| 時間帯 | 立ち姿 |
|---|---|
| morning | `wave` / `daydream` |
| day | `laptop` / `write` |
| afternoon | `snack` / `bored` |
| evening | `book` / `think` |
| night | `cards` / `laugh` |
| sleep | `sleep` |

振る舞い専用：`talk` / `worry` / `sulk` / `sleep`。

候補が2つある時間帯は、**日付で1枚に決めます**。見るたびに姿が入れ替わると落ち着きません。

#### 対応表（`sprites.json`）

器はこのファイルだけを見ます。**絵を足すときに触るのもこのファイルだけ**で、コードは変わりません。

```json
{ "sizes": { "full": [141, 140], "web": [413, 410], "face": [192, 192] },
  "sprites": { "talk": { "blink": true }, "laptop": { "blink": false } } }
```

まばたきの差分（`<名前>-blink.png`）は、素材フォルダーに置いて `build_sprites` を
走らせ直せば、そのまま載ります。**無い絵はまばたきしないだけで、動きます。**

#### 呼吸とまばたき

素材はポーズごとに1枚だけです。**呼吸は絵ではなくコードで作ります**——1.7秒の周期で
1ドット上下させるだけで、止まって見えなくなります。まばたきは差分がある絵だけ、
4〜10秒のばらつきで130ミリ秒。**等間隔にすると機械に見えます。**

繋がっていないあいだは薄く（不透明さ120）出して、沈んだ色で座って待ちます。
絵を足す必要はありません。

## API

新しいものは2本です。会話・通話・履歴は既存のものをそのまま使います。

| | 用途 |
|---|---|
| `GET /api/presence/stream` | 脳からの指示を受け取る（SSE、開きっぱなし） |
| `POST /api/presence/here` | 実体をこちらへ（通知から開いたとき、看板・立て札を押したとき、通話への誘導） |
| `POST /api/presence/bye` | 見えなくなった（`sendBeacon` で送る。[実装上の注意](#実装上の注意)） |
| `POST /api/chat` | 既存。**送信が呼び出しを兼ねます** |
| `POST /api/call` | 既存。`{"vessel": …}` を受け、**姿ごとその器へ移します**。実体が移れば切れます |

`POST /api/presence/bye` は器の都合を伝えるだけなので、実体の判断は脳が行います。

#### 器の名乗り

器は自分の名前を名乗ります。タスクトレイのドットは `desktop`、会話画面は `web-…`（開くたびに作る）。

| | 名前の渡し方 |
|---|---|
| `stream` | `?vessel=desktop` |
| `here` / `bye` | 本文の `{"vessel": …}` |
| `chat` | 本文に `vessel` を添える。**添えれば、送信が呼び出しを兼ねます** |

⚠️ `stream` と `bye` だけは、合言葉を `?token=` でも受けます。**EventSource も sendBeacon も、こちらから見出し（ヘッダー）を足せない**ためです。ほかの道は今までどおり見出しだけを見ます。

繋がっていない器を呼ぶと `409` です（実体は動きません）。

## 脳が送るもの

SSEで流す4種類だけです。**一方向で、器からの返事は期待しません。**

| 種類 | 中身 | 受け取った器がすること |
|---|---|---|
| `here` | — | 姿を出す |
| `away` | — | 外出中（看板・立て札）にする |
| `say` | `{text}` | ふきだし・吹き出しに出す |
| `act` | `{sprite, act}` | 絵を切り替える |

`say` に載せるのは**自発発言だけ**です。会話の返事は `POST /api/chat` が直接返すので、両方から出すと二重になります。判定は「同じ `turn_id` にユーザーの発言が無いこと」で行います（`messages` は `UNIQUE (turn_id, role)`）。

`act` を送るのは3つの場面です。**器は自分から見に行きません。**

| いつ | どこから |
|---|---|
| 器が繋がってきたとき | `/api/presence/stream` の入口 |
| 会話のあと（機嫌が動く） | `/api/chat`、`announce` |
| 巡回のたび（時間帯が変わる） | `jobs.run_periodic_jobs` |

送り先は実体のある器1つだけです。脳は**最後に送った姿を覚えていて、実体が移ったら移った先にも同じものを渡します**（移った先はまだ何も知らないため）。

## 処理フロー

### 実体化（デスクトップアプリの起動）

```
tray.pyw            脳（uvicorn）           ドット（mascot.pyw）
   │ ① 脳を子プロセスで起動
   ├──────────────────>│
   │ ② ドットを子プロセスで起動
   ├───────────────────────────────────────────>│
   │                   │<───────────────────────┤ ③ GET /api/presence/stream
   │                   │ ④ body = desktop
   │                   ├───────────────────────>│ here
   │                   │                        │ ⑤ 右下に姿を出す
```

⚠️ ドットが落ちてもトレイと脳は生き残ります。tray が子プロセスを見張って上げ直します（既存の仕組みに1件足すだけ）。

### 移動（会話画面で話しかけた）

```
会話画面                脳                      ドット
   │ ① POST /api/chat   │                        │
   ├───────────────────>│ ② body = web:xxx       │
   │                    ├───────────────────────>│ away
   │                    │                        │ ③ 手を振って消える → 立て札
   │                    │ ④ 会話（既存のまま）
   │ ⑤ 返事             │
   │<───────────────────┤
   │ ⑥ アバターが出る
```

⚠️ **②は④より先です。** 生成に数秒かかるので、先に実体を移さないと、返事が返るまでドットが喋る側に見えます。

### 発言（ことはのほうから）

```
巡回 ──> announce() ──> chat.speak() ──> 文ができる ──> messages に保存
                             │
                             └──> [通知の分かれ道](#通知の分かれ道)
```

### ドットから話しかける

```
ドット                     脳
   │ ① クリックで入力欄が出る
   │ ② Enter
   │ POST /api/chat        │
   ├──────────────────────>│ ③ 実体がドットでなければ、ここへ移す
   │  （ふきだしは「…」）  │ ④ 会話（既存のまま。turn_lock も記憶も同じ）
   │ ⑤ 返事                │
   │<──────────────────────┤
   │ ⑥ ふきだしに出す。10秒で引っ込む
```

⚠️ 履歴を遡る・読み上げ・通話は会話画面の仕事です。ドットは「ひとこと投げて、ひとこと返る」だけにします。

## モジュール

| ファイル | 役割 |
|---|---|
| `talk/figure.py` | 絵と振る舞いの判定。時間帯の区切りの唯一の持ち主 |
| `serve/hub.py` | 実体の管理、器の一覧、SSE配信 |
| `mascot/png.py` | PNGの読み書き（`zlib` のみ。8bit RGBA・非インターレース限定） |
| `mascot/sheet.py` | `sprites.json` を読み、拡大済み・プリマルチプライ済みのコマを持つ |
| `mascot/window.py` | レイヤードウィンドウ、ヒットテスト、ドラッグ |
| `mascot/bubble.py` | ふきだしと1行入力 |
| `mascot/client.py` | SSEの受信と再接続、POST |
| `mascot/__main__.py` | 組み立てと、絵を進める時計（呼吸・まばたき） |
| `mascot.pyw` | 入口。`pythonw.exe` から呼ぶとコンソールが出ない |
| `tools/make_dummy_sprites.py` | 仮素材の生成。**本番素材が来たら捨てます** |

`tray.py` の `Figure` が、本体と同じように子プロセスで見張ります。**落ちてもトレイと本体は無事**で、ここだけ出し直します。自分でしまったとき（終了コード0）は出し直しません。

変更するもの：`serve/web.py`（API2本）、`serve/announce.py`（分岐1つ）、`serve/static/app.js`（EventSourceと看板）、`talk/chat.py`（`figure.py` から読む・居場所を1行）、`talk/presence.py`（`idle_seconds()`）、`tray.py`（子プロセス1件）。

**新しい依存はありません。** PNGは `zlib` で読み、SSEは `StreamingResponse` で流し、ブラウザーは `EventSource` を標準で持っています。

## 設定

| キー | 既定 | 中身 |
|---|---|---|
| `KOTOHA_MASCOT_ENABLED` | on | ドットを出すか |
| `KOTOHA_MASCOT_SCALE` | 3 | 拡大倍率（整数のみ） |
| `KOTOHA_BODY_AWAY_MINUTES` | 5 | 何分の無入力でPushに切り替えるか |
| `KOTOHA_PUSH_WHEN_EMBODIED` | off | 実体があってもPushを鳴らすか |

## 実装上の注意

**① 見えなくなったことを、器から言わせる。**
iOSのPWAは背景に回ると動きが止まりますが、接続がすぐには切れないことがあります。切断だけを頼りにすると、**閉じたのに脳が「まだ居る」と思い込み、Pushが鳴らなくなります。** `visibilitychange` で `navigator.sendBeacon("/api/presence/bye")` を送ります。閉じる途中でも確実に届きます。

**② SSEは詰まることがある。**
Tailscale越しでレスポンスが溜め込まれると、リアルタイムのはずが遅れます。`X-Accel-Buffering: no` を付け、15秒ごとに `: ping` を流します（接続の維持も兼ねます）。

**③ レイヤードウィンドウにGDIで文字を描くと消える。**
`DrawTextW` は32bppのアルファを0のまま残すので、透過ウィンドウに描いた文字は見えません。**ふきだしは不透明な普通のウィンドウ＋角丸リージョン**（`SetWindowRgn`）で作ります。レイヤードなのはドット本体だけです。

**④ 押されたときの区別。** 押したまま4ドットより動かしたら「運んだ」、動かさなければ「押した」。**運んだ先は `data/mascot.json` に覚えます**（DBには入れません）。

**⑤ 透明な部分のクリックを抜く。**
レイヤードウィンドウは矩形全体でクリックを受けます。`WM_NCHITTEST` でその座標のアルファを見て、0なら `HTTRANSPARENT` を返します。アルファは手元にあるので1行です。

**⑥ 同じ姿を二重に出さない。** トレイと同じく名前つきの印（ミューテックス）と窓の有無で見る。上げ直しが重なると、ドットが2体並ぶ。

**⑦ 書き込みを増やさない。**
このDBはWALではありません（`busy_timeout = 5000`）。実体の居場所は移動したときだけ書き、巡回や表示のために書くことはしません。

## 作らないもの

判断がぶれないように、先に書いておきます。

- 器のためのLLM呼び出し（会話は `/api/chat` の1本だけ）
- 器のための機嫌（`app_state.mood` のまま）
- 器のためのテーブル（`app_state` に1つ書き写すだけ）
- 器から直接SQLiteを触ること（`turn_lock` の外で触らせない。必ずHTTP経由）
- ポーリング（実体の受け渡しはすべてSSEの押し出し）
- `look`（前面アプリが変わるたびに向き直る）、ドットからの通話（要ると分かってから）

## 段取り

各段階の終わりで、必ず動くものが残る順番です。

| | やること | 終わったときに確かめられること |
|---|---|---|
| 0 | `figure.py` を切り出す | 既存のテストが通る。二重管理の片方が消える |
| 1 | 素材の正規化ツール（`tools/build_sprites.py`） | `static/sprite/` に実寸の素材と `sprites.json` が出る |
| 2 | `hub.py` とSSE | 2つの器で、後から呼んだ側に `here` が届く。切れれば家に戻る |
| 3 | 会話画面を実体対応に | **2枚の画面で行き来が動く**（ドットはまだ無い）。`app.js` の二重管理が消える |
| 4 | ドット（器） | 右下に出る。話しかけると返る。追い出されると手を振って立て札になる |
| 5 | 仕上げ | 通話の統合、通話への誘導、居場所をプロンプトへ、README更新 |

⚠️ **3が山場です。** ここを越えると、いまの二重管理は解消され、残りは器を1つ足すだけになります。

### 通話の統合（段取り5）

`call_owner` / `call_seen_at` は実体の居場所に吸収します。通話は実体の中でしか始まらないので、実体が移れば通話は終わります。鮮度（`CALL_STALE_SECONDS`）の判定も要りません——SSEが切れた瞬間に脳が気づきます。

`tests/test_call_api.py` が試している内容（持ち主が入れ替わったら通話を止める）は変わっていません。呼ぶ先が変わり、**実体を移しただけでも通話が終わる**ことを1件足しました。

会話画面の5秒ごとの見張りも消えました。`away` を受けた器が、その場で自分の通話を切ります。
