# 07 運用と設定

## 始め方

叩くのは **`kotoha.bat` の1枚だけ**です（`kotoha.bat help` で一覧）。

| 順 | やること |
|---|---|
| 1 | `kotoha.bat setup` ── Python環境と依存3つ |
| 2 | `kotoha.bat settings` ── Geminiの鍵、合言葉、場所（緯度経度）など |
| 3 | `kotoha.bat tray` ── タスクトレイに常駐（推奨）。引数なしのダブルクリックでも動く |

ログイン時にも常駐させるなら `kotoha.bat autostart on`。

自分ぶんのファイルは `data/` に置きます（**git の外**）。

```
data/prompts/persona.txt     自分の人格。置くと prompts/ のひな形より優先される
data/calendars/garbage.json  ゴミの日
data/calendars/work.json     勤務時間と全体会議
```

書き方は [README](../README.md) にあります。置かなければ、その話題が出ないだけで動きます。

## 設定の変え方

3つの道があり、どれも同じ `.env` を書きます。

- **設定シート**（会話画面の歯車 → 設定）── 変えたらすぐ効きます（プロセスは止まりません）
- **`kotoha.bat settings`** ── 対話で
- **`.env` を直接** ── 直したら起こし直し

> ⚠️ 同じキーを2行書いた場合、**読むのは後ろの行**です。画面から直すと両方が書き換わります。

### よく触るもの

| 設定 | 既定 | 効き目 |
|---|---|---|
| `KOTOHA_WEB_TOKEN` | ― | 合言葉。空だと誰も入れません |
| `KOTOHA_LATITUDE` / `_LONGITUDE` | 東京駅 | 天気を見る場所 |
| `KOTOHA_BRIEFING_HOUR` | 7 | 朝のひとことの時刻（ゴミ収集が8時までに来るので7） |
| `KOTOHA_BACKUP_DIR` | 空 | **控えのもう1本**の置き場。空だとDBの隣だけ |
| `KOTOHA_NOTIFY_GAP_MINUTES` | 10 | これより近い通知はまとめます |
| `KOTOHA_PUSH_SHOW_TEXT` | true | 通知に本文を載せるか（載せるとOneSignalを通ります） |
| `KOTOHA_FAST_ENABLED` | false | 短い発言を軽い道に落とす |
| `KOTOHA_CODING_ENABLED` | true | Claude Code の様子を見る（記録の末尾の種類と時刻だけ） |
| `KOTOHA_DIARY_ENABLED` | true | 日付が変わったら前の日の日記を1件書く |
| `KOTOHA_DIARY_HOUR` | 0 | 何時から書いてよいか（PCが寝ていれば起きたとき） |
| `KOTOHA_STRENGTH_FLOOR` | 0.1 | 記憶の強さがこれを切ると消える |
| `KOTOHA_STRENGTH_GAIN` | 1.0 | 思い出したときに足す強さ（間が空くほど大きく） |
| `KOTOHA_STRENGTH_MAX` | 6 | 強さの上限 |
| `KOTOHA_MOOD_HALF_LIFE_HOURS` | 1 | 黙っているあいだに機嫌が半分に薄れるまでの時間 |
| `KOTOHA_TOPIC_KEEP_HOURS` | 24 | さっきまでの話題を持ち越す時間 |
| `KOTOHA_DIARY_RECALL_LIMIT` | 2 | 発言に意味の近い日記を会話に添える件数（意味の想起を切れば一緒に切れる） |
| `KOTOHA_REVIEW_ENABLED` | true | 日記を書いたあと1日1回、ここ1週間の記憶を寄せる・直す・閉じる |
| `KOTOHA_CODING_MIN_MINUTES` | 5 | これより短い作業では「終わった」と言わない |
| `KOTOHA_KEEP_AWAKE` | false | 常駐のあいだPCを寝かせない（[出先から立て直す](#出先から立て直す)） |
| `KOTOHA_VOICE_ENABLED` | ― | 読み上げ |
| `KOTOHA_EMBED_ENABLED` | ― | 意味での想起（Ollama） |
| `KOTOHA_DEBUG` | false | 詳しいログ。**合言葉がアクセスログに残る**ので、調べ終えたら戻す |

全項目は [.env.example](../.env.example) にあります。

## 外から使う（Tailscale）

Tailscale を入れてログインしておくと、起動時に配信まで行います。外からは同じ会話画面が開き、**iPhoneではホーム画面に置くとPWAとして動きます**（通知を受け取るにはホーム画面から開く必要があります）。

配信できないときは理由を出して、ブラウザは開きません。

## 出先から立て直す

**外から起こす手立てはありません。** 寝てしまえば Tailscale は応じず、Wake-on-LAN の合図は同じLANからしか届きません。だから外から立て直せるのは「**PCは起きていて、ことはだけが落ちている**」ときです。そこを厚くしてあります。

### 家で1回だけ用意する

| | やること | 効き目 |
|---|---|---|
| 1 | `.env` の `KOTOHA_KEEP_AWAKE=true` | 常駐しているあいだ**PCを寝かせない**。画面は消えます。電源設定そのものは書き換えません |
| 2 | `kotoha.bat rescue` の **1. Watchdog** | トレイごと落ちても、5分以内に戻ります |
| 3 | `kotoha.bat rescue` の **2. OpenSSH** | 最後の砦。**入口をひとつ開ける**ので、tailnet の中だけに留めること |

`kotoha.bat rescue` は管理者権限で、**家で1回**走らせるものです。外から叩く口ではありません。3つ目のステップ（高速スタートアップ）は、寝たPCを Wake-on-LAN で起こすための準備なので、1 を入れたなら要りません。

### iPhoneから、上から順に

| 見えている状態 | やること |
|---|---|
| 1. Tailscale アプリでPCが **offline** | 寝ているか、電源が落ちている。**外からは戻せません** |
| 2. URLは開くが、様子がおかしい | 設定（歯車）→ **再起動する**。トレイが上げ直します |
| 3. URLが開かない | **5分待つ。** 見張りがトレイを上げ直します |
| 4. それでも開かない | SSHで入って `schtasks /run /tn "Kotoha Watchdog"` |

SSHから戻すときは、**見張りのタスクを走らせます**。タスクは対話トークン付き（`/it`）で登録してあるので、**ログオンしている本人の画面**でトレイが立ち上がり、アイコンもデスクトップの姿も戻ります。`kotoha.bat tray` を直に叩くとSSHのセッションで動くので、**会話画面は使えるのに、家のPCには何も出ません**。

### 誰が誰を戻すか

| 落ちたもの | 戻すもの | かかる時間 |
|---|---|---|
| 本体（uvicorn） | トレイの見張り（`tray.py` の `Supervisor`） | 5秒 |
| デスクトップの姿 | トレイの見張り（`Figure`） | 5秒 |
| トレイごと | Watchdog タスク（5分ごと） | 5分以内 |
| 動いてはいるが様子が変 | 画面から再起動（`/api/restart` → 終了コード42） | すぐ |
| PCが再起動して、まだログオンしていない | **戻せません**（自動起動もWatchdogもログオン後） | ― |

> ⚠️ `KOTOHA_KEEP_AWAKE` は**トレイを起こし直すまで効きません**。設定シートには出していません。

## 控え（バックアップ）

- 自動：24時間ごと。手動：`kotoha.bat backup`
- 置き場：`data/backups/` と、設定していれば `KOTOHA_BACKUP_DIR`
- 戻すとき：CUIとWebを止め、既存DBを退避してから置き換えます

> ⚠️ **ことはの本体は記憶です。** 隣に1本しかないと、ディスクが1枚壊れた日にすべて消えます。別ドライブか同期フォルダーを指しておいてください。

## ログ

| ファイル | 中身 |
|---|---|
| `data/notify.log` | **黙って済ませない**ことの記録。巡回・整理・控え・通知の失敗、畳んだ頼まれごと |
| `data/tray.log` | 常駐の起動・終了・上げ直し |
| `data/actions.log` | ことはがPCに対してしたこと |
| `data/retrieve.log` | `KOTOHA_DEBUG=true` のときだけ。想起したID・タグ命中・`[USED:]` の申告 |

## 測っていること

**測ってから決める**ための数字です。どちらも挙動は変えません。

- **機嫌の発火率** ── `kotoha.bat status` に「機嫌が動いた回数（そのあいだ何ターン）」が出ます。「今の機嫌: ふつう」が壁紙になっていないかを見ます
- **想起と申告** ── `data/retrieve.log`。読んで使ったのに `[USED:]` が来ない記憶は、触れられていない扱いで消えます。その比を見てから、期限の延ばし方を決めます

## テスト

```
python -m tools.check
```

CI と同じ2つ（pyflakes → テスト）を順に回します。押す前にこれが通れば、向こうも通ります。テストだけなら `python -m unittest discover -s tests -t .`。

813件が手元で20秒ほど、CI（windows-latest）で55秒ほどで走ります。外への通信は塞いであり（**うっかり外を叩いたテストは失敗します**）、書き置きも本物の `notify.log` には残さず、本物の `~/.claude` も読みません。

どこに時間がかかっているかは、同じものをモジュールごと・1件ごとに測って出せます。CI もこちらで走らせています。

```
python -m tools.time_tests 20
```

時間の経過を確かめるテストは、`tests/support.py` の `Clock` で時計を止めて進めます（`kotoha/clock.py` が1本の時計で、DBの期限も機嫌の減衰も同じ「今」を見ます。SQLite の `'now'` は使いません）。

テストは毎回まっさらなDBから始めるので、DBを作る速さがそのまま効きます。表を揃えるのを1つのトランザクションにまとめて、1回 51ms → 5.6ms（手元で 29秒 → 10秒、CI で 3分 → 55秒）。

push と pull request のたびに、GitHub Actions が windows-latest で同じものを走らせます。

## 困ったとき

| 症状 | 見るところ |
|---|---|
| 返事が来ない | `data/notify.log`、Geminiの枠（429は投げ直しません） |
| 通知が来ない | 設定シートの通知欄、OneSignalの宛先、`notify.log` |
| 声が出ない | AivisSpeech が起きているか（見張りが落ちたときだけ知らせます） |
| 想起が効かない | Ollama が起きているか。タグ命中だけでも動きます |
| 画面から直したのに効かない | `.env` に同じキーが2行ないか |
| 出先で繋がらない | [出先から立て直す](#出先から立て直す)（Tailscale → 再起動 → 5分待つ → SSH） |
| どうにもならない | `kotoha.bat rescue`（管理者権限。**家で1回**、前もって） |
